앞의 글은 만든 사람의 말로 쓰여 있었습니다. 이번에는 쓰는 사람과 국민의 말로 바꿨습니다 — “화학사고가 나면 시·군·구 담당자에게 무슨 일이 벌어지는가”부터 시작합니다.

한 문장으로 줄이면 이렇습니다. “전문가가 없어도 대응할 수 있게, 안전원의 전문정보를 전국 지자체 담당자 손 안으로 옮겼다.”

먼저 짚어야 할 것 — 우리 도구에는 AI가 들어 있지 않습니다

받으신 평가는 이 사업을 AI 서비스로 보고 쓰인 듯합니다. 그런데 실제로는 서비스 안에서 AI가 판단하는 부분이 없습니다. “AI가 대피를 판단한다”고 발표하면 현장심사에서 “그 AI가 무엇을 하나요?” 한 질문에 무너집니다.

대신 사실에 맞으면서 더 센 카드가 있습니다 — 공무원이 생성형 AI를 도구로 써서 외부 용역 없이 직접 만들었다는 것. ’25년 대상작도 “공무원이 직접 기술을 개발”한 사례였습니다. 그리고 이렇게 쓰면 “AI가 재난을 판단해도 되느냐”는 위험한 질문 자체가 사라집니다.

그래서 서식에는 「외부 용역 없이 담당 부서가 직접 만듦 · 생성형 AI를 개발 도구로 활용」로 적고, 바로 아래에 “서비스 안에서 AI가 판단하지는 않음 — 정하는 것은 사람”을 붙였습니다.

사전심사 요약본 (1장)

화학물질안전원

전문가가 없어도 대응할 수 있게 — 화학사고 대응정보를 전국 지자체 담당자 손 안으로

추진배경(또는 목적)

  • 화학사고가 나면 시·군·구 담당자 한 사람이 주민 대피를 결정해야 하지만, 담당은 1~2명이고 대부분 처음 겪음
  • 사고 순간에 물질정보·표준문안·대피장소·방제자원 연락처를 각각 다른 문서에서 찾아야 했음
    • '26년 실제 사고에서 주민 대피 안내까지 46분(음성)·55분(서천) 소요
  • 전문정보는 안전원에 있는데 정작 쓸 사람 손에는 없었음 — 그동안은 전화로 한 건씩 알려 주는 방식

주요내용

  • 담당자가 사고 순간에 하는 일을 도구 세 개로 만듦
    • ①주민에게 보낼 문자 만들기(표준문안 12종) ②주민을 어디로 보낼지 찾기(대피장소 1,849곳)
    • ③방제 물품·장비 찾기 — "지금 무엇이 필요하세요?"부터 물음
  • 설치·회원가입·비밀번호가 없어 링크만 누르면 열리고, 인터넷이 끊긴 상황실에서도 파일 하나로 동작
  • 도구는 판단하지 않음 — 대피 여부와 장소는 담당자가 정하고 도구는 자료만 모아 보여 줌

주요성과(또는 기대효과)

  • 찾아 헤매던 자료를 한 화면에 — 물질 460종·표준문안 12종·대피장소 1,849곳·발송사례 42건
  • 방제 물품·장비 정보를 4.1배로 확대(470건→1,947곳), 개인정보 7,491건 제거
  • 빈칸이 남으면 문자를 만들지 않아 잘못된 문자 발송 위험을 없앰
  • 용역비·서버비 0원으로 담당 부서가 직접 개발, 유지비도 들지 않음
    • 전국 229개 시·군·구가 같은 자료로 대응하게 됨
추진 이전 (AS-IS)
  • 자료가 여러 문서에 흩어져 하나씩 찾아다님
  • 문자를 손으로 고쳐 쓰다 빈칸인 채 나갈 위험
  • 대피장소를 명단에서 눈으로 찾음
  • 인터넷이 끊긴 상황실에서는 쓸 수 없음
  • 지자체마다 가진 자료·준비 수준이 제각각
추진 이후 (TO-BE)
  • 링크 하나로 한 화면에서 확인
  • 빈칸이 있으면 문자를 만들지 않음
  • 가까운 순으로 자동 정렬(1,849곳)

추진배경(또는 목적)

  • 화학사고가 나면 시·군·구 담당자 한 사람이 주민 대피를 결정해야 함
    • 법상 주민대피 판단 책임은 시·군·구 / 담당은 보통 1~2명·순환보직
    • 대부분 화학사고를 처음 겪는 상태로 사고를 맞음
  • 사고 순간, 담당자는 네 가지를 동시에 찾아야 했음
    • ①무슨 물질이고 얼마나 위험한가 ②주민에게 문자를 어떻게 쓰나
    • ③어디로 대피시키나 ④방제 물품·장비는 누구에게 전화하나
  • 실제로 주민 대피 안내까지 46분·55분이 걸림
    • '26년 음성 수산화나트륨 10:03→10:49(46분) / 서천 황산 16:52→17:47(55분)
  • 전문정보는 안전원에 다 있는데, 정작 쓸 사람 손에는 없었음
    • 물질 460종 대응정보·재난문자 표준문안·전국 대피장소·방제자원 연락처 보유
    • 그동안은 사고 때마다 전화로 한 건씩 알려 주는 방식
    • → 그 정보를 전국 지자체 담당자의 손 안으로 옮기는 것이 이 사업의 목적

추진 내용(추진 경과)

  • 담당자가 사고 순간에 하는 일을 도구 세 개로 만듦
    • ① 주민에게 보낼 문자 만들기 — 승인된 표준문안 12종 중 맞는 문안 제시
    • ② 주민을 어디로 보낼지 찾기 — 전국 대피장소 1,849곳을 거리·도보시간 순
    • ③ 방제 물품·장비 찾기 — "지금 무엇이 필요하세요?"부터 물음
    • 문자는 기계가 문장을 조립하지 않고, 승인된 문장이 그대로 나옴
  • 컴퓨터를 잘 몰라도 쓸 수 있게 만듦
    • 설치·회원가입·비밀번호 없음 — 링크를 누르면 바로 열림
    • 한 화면에 한 가지만 물음 / 글씨를 키워도, 휴대전화에서도 그대로 보임
  • 인터넷이 없어도 열림 — 지자체 상황실은 대부분 망분리 컴퓨터
    • 파일 하나만 있으면 인터넷 없이 동작 — USB로 옮겨도 됨
  • 도구는 판단하지 않음 — 결정은 사람이 함
    • 대피 여부와 장소는 담당자가 정하고, 도구는 자료를 모아 보여 줄 뿐
    • 정확하지 않은 값에는 「대략」을 적고, 확인 못 한 값은 비워 둠
    • 대피장소는 공식적으로도 "최소한의 기준·지자체장이 탄력 적용"하는 것
  • (추진 경과) 자료 모으기 → 도구 만들기 → 확인 → 나눠 주기
    • 기관마다 따로 낸 파일 100여 개를 한 줄씩 펴서 표 18개로 정리
    • 도구 3종·첫 화면 개발, 정부 표준 디자인 적용, 자동 점검 18가지 구축
    • ①인터넷 링크 ②바탕화면 아이콘 ③인터넷 없는 PC용 파일 + 설명서 2종

장애요인 및 극복방법(또는 성공요인)

  • (어려움 1) 자료가 기관마다 제각각이라 그대로는 쓸 수 없었음
    • 파일 100여 개에 흩어져 있고, 같은 것을 부르는 이름이 19가지
    • (해결) 하나하나 펴서 표 18개로 정리하고 같은 뜻은 하나로 묶음
    • (해결) 가운뎃점처럼 보이던 글자가 다른 문자여서 '수집운반' 검색에 566건 중 1건만 나오던 것도 바로잡음
    • 같은 업종이 네 가지 이름으로 적혀 있어 같은 것을 네 번 봐야 했음
  • (어려움 2) 자료에 개인 이름과 휴대전화가 잔뜩 들어 있었음
    • 담당자 이름 2,719건·개인 휴대전화 495건 등 모두 7,491건
    • (해결) 전부 걷어내고 기관·회사 대표번호만 남김
    • (해결) 하나라도 남으면 나눠 줄 파일이 만들어지지 않도록 잠금장치
  • (어려움 3) 지자체 컴퓨터에서 안 열리면 아무 소용이 없음
    • (해결) 기능을 더하는 대신 덜어냄 — 서버·회원가입·설치를 없앰
  • (성공요인) 만드는 사람이 아니라 쓰는 사람의 말로 만듦
    • 현장에서 아는 것은 '무엇이 필요한가'이지 '자원의 분류'가 아니므로, ③은 "지금 무엇이 필요하세요?"로 시작
  • (성공요인) 외부 용역 없이 담당 부서가 직접 만듦
    • 업무를 아는 사람이 만들어 담당자 의견을 바로 반영, 생성형 AI를 개발 도구로 써 적은 인원·짧은 기간에 완성
    • 다만 서비스 안에서 AI가 판단하지는 않음 — 정하는 것은 사람
