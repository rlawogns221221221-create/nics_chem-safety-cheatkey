## 1. 바로 써 보기 — 심사위원 구동 순서

**가장 쉬운 길** — 휴대전화 카메라로 시연영상 마지막 화면의 QR을 비추거나, 브라우저에서 **https://chem-safety-kr.pages.dev** 를 엽니다.
첫 화면의 카드 4개(01 주민 대피장소 찾기 · 02 주민대피 문자생성기 · 03 방제 물품·장비 찾기 · 04 현장 안전거리 확인) 중 하나를 누르면 바로 시작합니다.
PC에서도 같은 주소를 엽니다. 넓은 화면에서도 기능은 같습니다.

**이 저장소로** — 내려받아 뿌리의 `index.html` 을 더블클릭하면 그대로 열립니다(서버 필요 없음).
또는 이 폴더에서 `python3 -m http.server 8000` → http://localhost:8000

**업무망 PC(인터넷 없음)** — `dist/` 의 HTML 파일 4개 중 하나를 더블클릭합니다. 자료와 지도 경계선·검색 색인이 파일 안에 들어 있어 인터넷 없이 작동합니다.

PC에서 04의 「내 위치 확인」은 PC 위치로 잡히므로, **지도를 누르면 그 자리가 구역 안인지** 같은 방식으로 확인할 수 있습니다.

## 2. 왜 만들었나 — 사고 현장에서 꼭 필요한 정보가 흩어져 있음

화학사고가 나면 지자체 담당자는 짧은 시간 안에 ① 주민 대피장소 결정 ② 재난문자 발송 ③ 방제 물품·장비 확보를 해야 하고,
현장 인원은 ④ 내 자리가 안전거리 안인지 확인해야 합니다. 그러나 필요한 자료가 기관마다 **엑셀, 한글, PDF, 스캔 문서 등 19종**으로
흩어져 있어 유선 확인과 개별 섭외에 의존하고 대응이 늦어집니다. 초동대응이 늦어지면 주민 대피와 오염 확산 차단도 함께 늦어지므로,
**국민 안전과 직결되는 공공 과제**입니다.

> 수습 지연 사례: 울산 암모니아 누출('23, 19시간), 창원 황산 누출('23, 11시간), 화성 유해물질 누출('24, 40일간 처리)

| 해야 할 일 | 지금까지의 어려움 | 이 서비스 |
|---|---|---|
| ① 주민을 어디로 | 대피장소 목록(1,849곳)과 이재민 임시주거시설(15,905곳)이 따로 있어, 사고지점 기준으로 함께 가까운 순으로 보기 어려움 | 사고지점 하나 → 두 층을 나눠 **가까운 순 · 반경별 개수 · 도보시간** |
| ② 주민에게 알리기 | 재난문자 표준문안(안)을 손으로 채우다 빈칸·오타가 남을 수 있음 | **한 화면에 한 가지씩** 묻고, 필수 칸이 다 차야만 **표준문안 그대로** 문안 |
| ③ 방제 자원 구하기 | 방제자원 원자료가 **3,865곳 · 8,266줄**, 엑셀·한글·PDF·**스캔 허가증**으로 기관마다 흩어짐 | **업체 섭외 1,717건 · 방제물품 4,075건(자리 2,341곳)** 으로 묶어 가까운 순 · 연락처 · 수량 |
| ④ 내가 선 자리는 | 물질별 초기이격·방호활동 거리는 물질정보에 글로 적혀 있어, 현장에서 바람·내 위치와 바로 견주기 어려움 | 물질 **460종의 ERG 거리**를 지도 구역으로 그리고 **내 위치가 안인지 계속** 표시 |

### 추진 과정과 성과 — 현장 조사부터 설문 반영까지

방제자원 현장 조사('24.2~, 공공·민간 3,865개소, 사업장 46개소 방문) → 화학사고 1,038건 AI 분석('26.8) → 서비스 개발('26.9)
→ 243개 지자체 시범운영('26.9.9.~) → 설문 의견을 반영해 04 현장 안전거리 확인(초기이격거리)과 상황 공유 추가('26.11)

- **실제 사고 활용** — 제주 염소가스 사고('26.10.1.) 때 도내 업체 확보가 어려웠으나 서비스 조회로 섭외 요청 25분 만에 도외 업체 확보
- **시간 단축** — 초동 자료 확인 20~30분 → 3분 이내, 재난문자 문안 작성 15분 → 2분 이내(추정), 확인할 자료 19종 → 주소 1개,
  자원 확인 체감 3시간 이상 → 약 3분(2개 지자체 응답)
- **비용 절감** — 별도 예산과 발주 없이 구축, 서버가 없어 유지비도 들지 않아 기관이 늘어도 추가 비용 없음
- **시범운영 설문(지자체 담당자 58명)** — 업무 도움 **75.9%**(도움 안 됨 **0명**), 만족 **72.4%**, 사용이 쉬움 **65.5%**
  - 많이 쓴 기능: 주민 대피장소 47명 · 방제 물품·장비 46명 · 문자생성기 28명(복수 응답) · 실제 사고 대응에 활용 5명
  - 개선 의견(정보 보완·최신화 19명, 방제물품 세분화 등)은 다음 과제로 두었습니다

## 3. 무엇이 다른가 — 사고지점 하나로, 휴대전화 하나로

1. **사고지점 하나로 네 가지 확인.** 같은 사고지점으로 대피장소 → 재난문자 → 방제자원 → 안전거리를 이어서 확인합니다. 01에서 고른 대피장소가 02 문자의 칸으로 그대로 넘어가고,
   04에서 정한 사고지점·물질이 01·02로 넘어갑니다. 같은 값을 네 번 치지 않습니다.
2. **문자는 "만드는" 것이 아니라 "승인된 문안을 채우는" 것입니다.** 문장을 조립하거나 생성하지 않고,
   빈 필수 칸이 있으면 문안 자체를 내놓지 않습니다 — 반쪽 문안이 그대로 발송될 위험을 막습니다.
3. **물질정보의 글을 지도 위 구역으로.** 「화학사고 현장대응 물질정보」 460종에 글로 적힌 ERG 거리
   (육지/수계 · 기체/액체 · 소·대규모 · 낮·밤 등 표기가 물질마다 다름)를 숫자로 읽어 그립니다.
   **460종 전부, 원문의 숫자 개수와 읽은 개수를 기계로 대조**합니다. 낮·밤은 사고지점의 일출·일몰로 정합니다.
4. **서버 없는 상황 공유.** 04의 「상황 공유」는 물질·사고지점·조건을 **링크 하나**에 담아 문자·메신저로
   보냅니다. 받은 사람이 열면 같은 구역이 그려집니다. 서버·계정·DB가 없고, **보낸 사람의 내 위치는 담지 않습니다.**
5. **인터넷이 끊겨도.** 같은 기능을 **파일 하나**로 업무망 PC에서 엽니다(자료·지도 경계선·검색 색인 포함).
6. **휴대전화가 먼저.** 링크나 QR 하나로 열고 한 화면에 한 가지씩 묻도록 만들어, 순환보직으로 바뀐 담당자도 교육 없이 씁니다.
   현장에서 꺼내 쓰는 도구라 390px 화면에서 먼저 맞추고, 손가락으로 누르는 것은 40px 이상,
   고대비(어두운) 화면과 화면낭독기를 지원합니다(정부 디자인 시스템 KRDS 토큰).

### AI를 어떻게 썼나

**만드는 데 AI를 썼고, 판단은 사람이 합니다.**

- **개발** — 개발자가 아닌 **담당 공무원이 AI 코딩 도구(Claude Code)와 대화하며** 화면, 자료 정리, 점검 코드를 직접 작성했습니다
  (약 4주, 수정 기록 99회). 자동 검증 20묶음까지 모두 이 방식입니다.
- **자료 정리** — 흩어진 원자료를 AI로 정리했습니다. 자세한 것은 [자료 정리와 AI 활용](docs/자료_정리와_AI활용.md).
  - 스캔 이미지뿐인 **폐기물처리 허가증 24건을 판독**해 허가 갈래·처리가능 폐기물·주소·대표번호를 표로
  - 기관마다 달랐던 방제물품 표기 **674가지**를 급할 때 부르는 단위의 **표준 27가지**로 (원래 이름은 남김)
  - 원자료에 섞여 있던 **담당자 실명 2,719건 · 개인 휴대전화 495건을 걷어냄** — 배포할 때 기계로 다시 검사
  - 물질 460종의 ERG 거리 문장을 숫자로 바꾸는 규칙을 만들고 **460종 전부 대조**
- **사고 분석** — 화학사고('15~'25) **1,038건**을 AI로 분석해 7개 물질군으로 분류하고, 매뉴얼과 물질안전보건자료로 보정해 산단별 동원순위(안)를 마련했습니다.
- **실행 중에는 AI 모델을 부르지 않습니다(AI 신뢰성 확보)** — 일부러 그렇게 정했습니다.
  ① 재난문자는 **승인받은 표준문안만** 나가야 하고(AI가 지어낸 문장이 섞이면 안 됨) ② 인터넷이 끊긴 **업무망 PC나 사고 현장에서도
  같은 결과가 몇 초 안에** 나와야 하며 ③ **AI 서비스 장애나 사용료와 상관없이** 언제나 운영할 수 있어야 하기 때문입니다.
- **모델 교체(이식성)** — 실행에 모델이 들어 있지 않아 특정 AI에 묶이지 않습니다. 기능을 고칠 때는 공통기반 지원 모델 등
  다른 코딩 AI로도 같은 소스를 수정할 수 있습니다.

## 5. 다른 기관에서 쓰기 — 확산

- **전국 자료** — 대피장소·임시주거시설·방제자원 모두 전국 단위입니다. 어느 시·군·구에서도 바로 쓸 수 있습니다.
- **정적 파일뿐** — 서버·DB·빌드 도구·외부 라이브러리가 없습니다. 아무 웹 서버(기관 홈페이지, Pages 서비스)에
  폴더째 올리면 끝입니다. `python3 build/make_release.py` 가 **개인정보 검사를 통과한 배포 폴더**와 업무망용 단일 파일을 만듭니다.
- **자료 갱신이 스크립트 한 줄** — 원자료를 바꾸고 스크립트를 다시 돌리면 화면 자료가 새로 만들어집니다.
  이재민 임시주거시설은 행정안전부 재난안전데이터공유플랫폼 **오픈API**로 받습니다(`build/fetch_tempshelter.html` — 인증키는 각 기관의 것을 넣음).
- **오래된 행정망 브라우저에서도** — 화면 코드는 ES5 문법(화살표 함수·let 없음)으로 썼습니다.
- **같은 틀로 다른 재난에** — 지도 엔진(`assets/mapcore.js`)과 "사고지점 → 가까운 순 → 연락처" 흐름은 자료만 바꾸면
  가스, 수질오염 사고 등 다른 재난·시설 찾기에도 그대로 쓸 수 있습니다.
- **비용** — 별도 예산과 발주 없이 구축했고, 서버가 없어 유지비도 들지 않아 기관이 늘어도 추가 비용이 없습니다.
- **지속 운영과 확대** — 자료 반기 1회 최신화, 2차 대상 확대(화학재난 합동방재센터, 유역환경청, 소방 상황실).

```bash
python3 build/make_resources2.py  # 방제자원 통합 표(docs/방제자원_정리/통합) → data/resources2.js
python3 build/build_single.py     # 업무망 PC용 단일 파일 → dist/
python3 build/make_release.py     # 다른 기관에 넘길 배포 폴더(개인정보 검사)
tests/run.sh                      # 화면 자동 검증 20묶음
```

대피장소·물질정보의 원자료(`source/` · 기관 엑셀)는 이 묶음에 넣지 않았습니다 — 받은 원자료를 `source/` 에 두고
`python3 build/make_data.py` 를 돌리면 `data/` 가 다시 만들어집니다(openpyxl 필요).

## 8. 인터넷이 있을 때만 더해지는 것 · 알려진 제약

- 배경지도(브이월드 → 안 되면 OpenStreetMap 자동 전환) · 주소·장소 검색(브이월드) · 도보 경로(OSRM).
  없으면 그 기능만 빠지고 **행정경계선 위에서 나머지는 그대로** 동작합니다.
- 04의 구역은 **확산 모델링이 아니라 물질정보에 적힌 ERG 참고 거리**를 그린 것입니다. 바람·지형·용기 크기에 따라
  실제와 다를 수 있다고 화면 자료 출처에 적었습니다. 바람 방향을 고르지 않으면 거리만 점선 원으로 보여 줍니다.
- 판단은 담당자가 합니다. 서비스는 자료를 가까운 순으로 모아 보여 줄 뿐이며, 대피 여부와 범위, 동원 업체는 담당자가 결정합니다.
- 거리는 직선거리, 도보시간은 그 거리로 계산한 값, 일부 방제자원 위치는 주소로 잡은 대략 위치(지도에 속이 빈 표시)입니다.
- 자료의 한계: 기관마다 기준일이 달라 화면에 기준일을 표시하고 반기 1회 최신화할 예정입니다.
  이재민 임시주거시설 원자료에는 관리기관·전화가 없어 비워 둡니다(지어 넣지 않음).
- 내 위치는 휴대전화 위치 기능을 써서 실내에서는 오차가 클 수 있으며, 위치 정보는 외부로 보내지 않습니다.
- 행정경계선은 통계청 센서스용 경계(2018) 단순화본으로 법적 경계가 아닙니다.
