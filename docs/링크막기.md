# 퍼진 링크 잠시 막기 (그리고 다시 열기)

시범운영 안내 전에 링크가 여러 곳으로 전달되어, **접속을 잠시 닫아 두는**
방법입니다. 나중에 다시 열 때도 **같은 주소를 그대로** 씁니다 —
주소를 버리면 이미 저장해 둔 사람들이 다시 못 찾습니다.

---

## 0. 지금 살아 있는 주소는 둘입니다

| | 주소 | 누가 만들었나 | 누가 막을 수 있나 |
|---|---|---|---|
| ㉮ | `https://chem-safety-kr.pages.dev` | 사용자가 Cloudflare 에 직접 올림 | **사용자만** (2절) |
| ㉯ | `https://rlawogns221221221-create.github.io/nics_chem-safety-cheatkey/` | 저장소의 자동 배포 | 이미 막았습니다 (1절) |

지자체에 나눠 준 것은 ㉮ 이지만, ㉯ 도 **같은 도구가 통째로 올라가 있는
공개 주소**입니다. 하나만 막으면 반만 막는 것이라 둘 다 다룹니다.

---

## 1. ㉯ 깃허브 주소 — 막았습니다 ✔

`.github/workflows/pages.yml` 의 **한 줄**이 열림/닫힘을 정합니다.

```yaml
env:
  SITE_OPEN: "no"      # "yes" 로 바꾸면 다시 열립니다
```

`"no"` 이면 도구·자료·단일파일을 **아예 올리지 않고**,
`build/닫힘안내.html` 한 장만 `index.html` 로 올립니다.
안 올리면 `…/res/` 처럼 **주소를 직접 쳐서 들어가는 길도 함께 막힙니다.**
검색에 잡히지 않도록 `robots.txt` 도 함께 올립니다.

> **워크플로 파일을 지우는 것으로는 안 막힙니다.** 지우면 *자동 배포*만
> 멈출 뿐, **이미 올라가 있는 사이트는 그대로 살아 있습니다.** 그래서
> 지우지 않고 안내문으로 덮어씁니다.

**주소 자체를 없애려면** 사용자가 저장소에서 한 번 눌러야 합니다 —
`Settings` → 왼쪽 `Pages` → `Build and deployment` → `Source` 를
**`None`** 으로. 워크플로에 주어지는 토큰에는 그 권한이 없어 제가 못 합니다.
다만 굳이 안 해도 됩니다. 안내문만 남아 도구는 열리지 않습니다.

---

## 2. ㉮ Cloudflare 주소 — 사용자가 눌러야 합니다

이 개발 환경은 바깥 인터넷으로 나갈 수 없어(`dash.cloudflare.com` 도 막힘)
제가 대신 눌러 줄 수 없습니다. 셋 중 하나를 고르세요.

### 길 ①  안내문으로 덮어쓰기 — **권장**

이미 링크가 퍼졌으니, 들어온 사람이 **죽은 링크(오류 화면)** 를 보면
담당자에게 전화가 옵니다. "지금은 닫혀 있다"는 안내문 한 장이 낫습니다.

1. `build/닫힘안내.html` 을 내려받아 **이름을 `index.html` 로** 바꿉니다.
2. 빈 폴더를 하나 만들고(예: `닫힘`) 그 파일 하나만 넣습니다.
3. <https://dash.cloudflare.com> → **Workers & Pages** →
   **`chem-safety-kr`** 프로젝트를 엽니다.
4. 새 배포를 만드는 곳에서 **그 폴더를 통째로 끌어다 놓습니다.**
   (처음 올릴 때와 같은 자리입니다 — `Upload assets` 로 올렸던 그 화면)
5. 올라가면 주소를 열어 **안내문이 나오는지** 확인합니다.

이러면 도구 파일이 서버에서 사라지므로, `…/res/` 같은 주소를 직접 쳐도
안내문(또는 없음)이 나옵니다.

> ⚠ Cloudflare 화면의 단추 이름은 제가 **확인하지 못했습니다**(위 이유).
> 처음 올릴 때 쓴 `Upload assets` 흐름과 같은 자리입니다. 화면이 다르면
> 그 화면을 찍어 보여 주세요 — 그 자리에서부터 알려 드리겠습니다.

**다시 열 때** — `python3 build/make_release.py` 로 만든
`release/화학사고_초동대응_지원_서비스/` 폴더를 같은 자리에 다시 끌어다
놓으면 됩니다. 주소는 그대로입니다.

### 길 ②  아는 사람만 들어오게 하기 (Cloudflare Access)

지자체 담당자는 계속 쓰게 하고 **모르는 사람만** 막고 싶을 때입니다.
Cloudflare 의 **Zero Trust → Access** 로 이 사이트 앞에 **이메일 확인**을
세웁니다. 허용한 이메일(예: `@korea.kr`)로 들어온 사람에게만 열립니다.

- 좋은 점 — 링크가 더 퍼져도 아무나 못 들어옵니다.
- 나쁜 점 — 담당자도 처음에 **이메일로 온 번호**를 넣어야 합니다.
  급할 때 쓰는 도구라 이 한 걸음이 부담일 수 있습니다.
  무료 요금제의 사용자 수 한도도 확인이 필요합니다.

> 이 길의 화면 이름·설정 순서도 제가 **확인하지 못했습니다.**
> 이 길로 가기로 정하시면 알려 주세요 — 화면을 보면서 함께 하겠습니다.

### 길 ③  프로젝트 통째로 지우기

가장 확실합니다. 프로젝트 설정 맨 아래의 **삭제**를 누르면 주소가 없어집니다.

- ⚠ **`chem-safety-kr` 이라는 이름을 남이 가져갈 수 있습니다.** 지운 뒤에는
  그 주소가 비어서 누구나 같은 이름으로 만들 수 있습니다. 이미 그 주소가
  여기저기 퍼져 있는 상황이라, **다시 열 생각이면 지우지 마세요.**
- 지웠다가 같은 이름으로 다시 만들 수 있을지는 **확인하지 못했습니다.**

## 3. 링크가 더 퍼지는 것 줄이기

막는 것과 별개로, 지금 해 두면 좋은 것입니다.

- **검색에 안 잡히게** — 닫힘 안내문에 `noindex` 를 넣었고 `robots.txt` 도
  함께 올립니다(1절). 다시 열 때는 이 둘이 **빠져야** 합니다 —
  `make_release.py` 가 만드는 배포 폴더에는 원래 없습니다.
- **다음에는 이름을 알아보기 어렵게** — 다시 열 때 `chem-safety-kr` 대신
  `chem-safety-kr-2026pilot` 처럼 **짐작하기 어려운 이름**으로 새로 올리면,
  퍼진 옛 주소로는 아무도 못 들어옵니다. 옛 주소에는 안내문만 남겨 둡니다.
  (주소를 바꾸면 `docs/배포하기.md` 의 안내문과 브이월드 인증키의 활용
  도메인, 그리고 설명서 PDF 두 가지의 주소도 함께 고쳐야 합니다)

## 4. 다시 열 때 확인할 것

1. `.github/workflows/pages.yml` 의 `SITE_OPEN` — 깃허브 주소도 열지
   말지 정하세요. **지자체에 나눠 주는 주소가 아니므로 `"no"` 로 두는
   것을 권합니다.**
2. Cloudflare 에 `release/…` 폴더를 다시 올렸는지.
3. 주소를 열어 **카드 세 장을 눌러 도구 세 개가 다 열리는지.**
   (닫아 둔 동안 파일이 사라져 있었으므로 꼭 눌러 보세요)
4. 배경지도가 나오는지 — 주소가 바뀌었다면 브이월드 인증키의
   **활용 도메인**에 새 주소를 등록해야 합니다(`docs/배포하기.md`).
