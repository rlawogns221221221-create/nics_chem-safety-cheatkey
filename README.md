# 화학사고 지자체 대응 지원도구

화학사고 발생 시 지자체 담당자의 초기 대응 업무를 돕는 정적 HTML 도구 모음입니다.
**별도 서버 없이** 홈페이지 게시 또는 파일 배포만으로 동작합니다.

| 도구 | 폴더 | 진입 화면 순번 | 상태 |
|---|---|---|---|
| 주민대피 문자생성기 | `sms/` | 03 | **초안 (v0.5.0-draft)** |
| 주민 대피장소 찾기 | `map/` | 02 | **초안 (v0.5.0-draft)** |
| 방제 물품·장비 찾기 | `res/` | 01 | **초안 (v0.5.0-draft)** · 예시 자료 |

> 진입 화면은 **실제 업무 순서**로 늘어놓습니다 — 지도에서 어디로 대피시킬지
> 정한 다음, 그 내용을 그대로 들고 문자를 씁니다(지도 화면의 *이 내용으로 문자
> 만들기* 단추). 이 문서 안의 ①·②·③ 은 만들어진 순서(①`sms/` ②`map/` ③`res/`)
> 이며 진입 화면의 번호와 다릅니다.

---

## 진입 화면 (index.html)

세 업무도구로 들어가는 대표 화면입니다. **KRDS(대한민국 정부 디자인시스템)
표준형**이고 `assets/portal.css` 하나만 씁니다. 바깥으로 나가는 요청은 0건입니다
(글꼴·사진 모두 저장소 안에 있습니다).

**구성** — 흰 상단 바(기관 로고 + 서비스명, 아래 굵은 파란 선) → 산업단지 실사
사진이 5초마다 바뀌는 머리 띠 → **카드 3장 한 덩어리** → 참고도구 알림 → 꼬리.

- 카드는 평소에 **`01 이름` 한 줄과 사진**만 보이고, 마우스를 올리거나 키보드
  초점이 오면 설명과 자료 건수가 사진 위로 올라옵니다(사용자 요청). 감추는 것이
  아니라 비켜 두는 것이라 화면낭독기는 늘 읽고, 호버가 없는 기기와 인쇄에서는
  처음부터 펼쳐집니다.
- 카드 세 장은 **칸 사이를 붙인 한 덩어리**이고 머리띠에 딱 붙습니다. 테두리와
  둥근 모서리는 띠 바깥에 하나만 둡니다.
- 자바스크립트는 **단추 두 개**에만 씁니다 — 고대비(어두운) 화면
  (`assets/theme.js`)과 머리띠 사진 넘김 멈춤(`assets/portal.js`). JS 를 꺼도
  카드 링크도 사진 넘김도 그대로 동작합니다 — `tests/t9` 가 JS 를 끈 채로도
  확인합니다.
- 세 도구 모두 완성되어 각 카드에 실제 링크가 걸려 있습니다. (③ 을 만들기 전에는
  `<a>` 자체를 두지 않고 `tabindex="0"` 만 뒀습니다 — 쓸 수 없는 것에 가짜 링크를
  걸지 않기 위한 것으로, 앞으로 도구를 더 늘릴 때도 같은 방식을 쓰면 됩니다.)
- **카드 순서는 `01 방제 물품·장비 찾기 → 02 주민 대피장소 찾기 →
  03 주민대피 문자생성기`** 입니다. 차례와 이름은 **사용자가 정합니다** —
  한동안 `주민 대피장소 찾기 → 주민대피 문자생성기 → 방제 물품·장비 찾기` 였습니다
  (상사 피드백). 임의로 되돌리지 마세요.

### 기관 로고

상단 바 왼쪽의 로고는 원본 파일을 **자르거나 배경을 손대지 않고 그대로**
씁니다(`assets/img/gov-logo.png` — `source/책임운영기관_기후에너지환경부_화학물질안전원.png`
와 바이트 단위로 동일). 배지·부처명·기관명이 이미 이미지 안에 다 있어서
`index.html` 에 같은 글자를 텍스트로 또 넣지 않습니다. 뒤에 오는
"화학사고 초동대응 지원 서비스" 만 별도 텍스트입니다(이건 이미지에 없는, 이 화면
고유의 서비스명이라 중복이 아닙니다).

로고 묶음은 왼쪽, "누리집" 링크는 오른쪽 — 흔한 관공서 상단 바 배치입니다.
가운데 정렬을 시도했다가 되돌린 적이 있는데, 왼쪽 정렬이 낫다는 의견을 받아
원래대로 뒀습니다.

### 카드 세 장은 칸 사이를 붙인 한 덩어리입니다

두 번의 지적을 거쳐 지금 모양이 되었습니다.

1. 처음에는 카드마다 테두리를 두고 2.4rem 간격을 벌려 두었습니다 →
   **"박스 사이의 공백이 오히려 전문성을 줄인다"** → 세 장을 붙이고 테두리는
   바깥에 하나만 둘렀습니다.
2. 그래서 화면 끝까지 늘려 봤습니다 → **"화면 비율이 완전히 바뀌어 오히려
   가독성이 떨어졌다"** (한 칸이 620px 을 넘자 사진이 커지고 글자가 흩어짐) →
   크기는 가운데 상자(120rem)로 되돌리고, **붙이는 것만** 남겼습니다.

- 칸 사이는 머리카락 같은 선 하나뿐입니다(`.tools` 의 `gap:.1rem` 자리에 띠의
  바탕색이 보입니다). 테두리·둥근 모서리는 **띠 바깥에 하나만** 둡니다.
- 카드마다 테두리·모서리·그림자를 주면 다시 '따로 노는 상자'가 되므로 주지
  않습니다. 마우스를 올리면 글자 칸 바탕이 아주 옅은 파랑으로 물듭니다.
- 초점 표시는 **안쪽으로** 그립니다(`--focus-in`). 카드끼리 붙어 있어 밖으로
  그리면 옆 카드 위로 테가 넘어갑니다.
- **로고 · 머리띠 제목 · 카드 띠 · 알림 · 푸터의 왼쪽 끝이 한 줄에 섭니다**
  (`--edge`). `tests/t9` 가 세 지점을 재서 확인하고, 띠가 상자 폭을 넘지
  않는지도 함께 봅니다.

### 첫 화면은 어떻게 구성되어 있나

위에서 아래로 **머리띠 사진 → 카드 띠 → 작은 안내문 → 푸터** 넉 줄이고,
1440×900 화면에서 스크롤 없이 다 들어옵니다.

- **카드 띠는 머리띠에 딱 붙습니다.** 사이에 '업무도구 3종' 제목이 있어 틈이
  생겼는데 사용자가 그 틈을 없애 달라고 했습니다. 제목은 화면에서 빼고 문서에는
  남겼습니다(`.sr-only`). 띠의 위쪽 모서리는 각을 살리고 아래만 둥글립니다 —
  사진에서 카드로 **세로로 이어지는 한 덩어리**로 보이게 하려는 것입니다.
- **카드에 평소 보이는 글자는 `01 이름` 한 줄뿐입니다.** 자료 건수·기준일은
  설명과 함께 사진 위 판으로 옮겼습니다. 손가락 기기에서는 판이 늘 펼쳐져
  있으므로 자료 건수만 비켜 둡니다(화면낭독기는 그대로 읽습니다).
- **'업무 참고도구입니다' 는 색 띠 없이 작은 회색 글줄**입니다. 노란 띠였던
  것을 눌렀습니다 — 다만 **지우지 않습니다.** 크기·대비는 읽을 수 있는 선
  (`--ink2` · 14px)을 지켰고, `tests/t9` 가 색 띠 없음·진하기·글자 수를 함께
  검사합니다(흐리게 만들거나 지우면 실패합니다).

### 머리띠 — 사진과 문구가 5초마다 바뀝니다

"제목 문구가 너무 정적"이라는 지적, 그리고 "긴 배경화면 사진이 5초쯤마다
바뀌면서 문구도 다른 문구로 바뀌었으면 좋겠다"는 요청을 이렇게 풀었습니다.

- 서비스 이름은 기관의 **공식 이름이라 글자를 바꾸지 않고**, 낱말로 나눠
  (`<span>`) 열 때 0.1초 간격으로 하나씩 올라오게 했습니다.
- 산업단지 실사 사진 **다섯 장**과 문구 **다섯 줄**이 짝을 이뤄 5초마다 함께
  넘어갑니다(한 바퀴 25초). 사진은 제 차례에 아주 조금 컸다가(1.04) 제자리로
  내려앉습니다. 아래에 지금 몇 번째인지 알려 주는 점 다섯 개가 있습니다.
- **문구는 지어내지 않았습니다.** 네 줄은 도구가 하는 일과 자료 건수
  (1,849곳 · 표준문안 12건 · 사례 42건 · 자원 470건 — 카드에 적힌 값과 같은
  숫자입니다. `tests/t9` 가 두 값이 같은지 대조합니다). 마지막 한 줄은
  "이 도구는 판단하지 않습니다" — 이 도구의 원칙입니다.

지켜야 할 것 네 가지

1. **넘김은 CSS 만으로 합니다.** 자바스크립트를 꺼도, 망분리 PC 의 단일
   파일에서도 그대로 넘어가야 합니다.
2. **안 보이는 문구 네 줄도 문서에 그대로 있습니다**(`opacity` 만 0).
   화면낭독기는 다섯 줄을 다 읽습니다 — 움직임 뒤에 자료를 숨기지 않습니다.
3. **멈춤 단추**가 있어야 합니다(KRDS·WCAG 2.2.2 — 5초를 넘겨 저절로 움직이는
   것에는 멈출 방법을 준다). `assets/portal.js` 가 만들어 답니다. 누르면
   `<html data-hero="stop">` 이 붙고 CSS 가 `animation-play-state:paused` 로
   **그 자리에 세웁니다**(지우면 첫 장으로 되돌아가 버립니다). 고른 값은
   저장해 두어 도구를 다녀와도 그대로입니다.
4. 다섯 줄은 **한 칸에 겹쳐** 둡니다(`.hero-leads` 가 grid). 세로로 쌓으면
   줄 수가 다른 문구로 넘어갈 때마다 띠 높이가 들썩입니다.

모션을 줄이는 설정에서는 넘김을 **끄고 첫 장만** 보여 줍니다. 그 설정에서는
멈춤 단추도 만들지 않습니다 — 아무 일도 못 하는 단추는 눌러 보고 고장인 줄
압니다.

⚠ 사진 다섯 장은 **비슷한 것을 나란히 두지 마세요.** 눈높이 파노라마와 수직
항공사진을 번갈아 놓았습니다(`build/make_site_images.py` 의 `CROP` 차례).
닮은 두 장이 잇달아 나오면 바뀐 줄 모르고 화면이 잘못된 것처럼 보입니다.

### 좁은 화면 — 카드 한 장이 사진 한 장

사용자 요청입니다 — "모바일에서는 설명은 지우고 제목만. 사진 위에 글을 쓰는
거야. 칸이 지금보다 좀 더 좁아지는 거지."

```
┌─────────────────────────┐
│                         │
│      사진 (7:3)          │
│                         │
│  ▁▁▁▁▁▁▁▁▁▁ 짙은 판 ▁▁▁  │
│  [02] 주민 대피장소 찾기  (→) │  ← 사진 위에 얹은 제목
└─────────────────────────┘   한 칸 153px
```

- **흰 글자 칸이 없습니다.** 사진 한 장이 곧 카드이고, 제목은 사진 아래쪽에
  얹습니다. 그 자리에 짙은 판(`--ov` 그라데이션)을 깔아 사진 밝기에 기대지
  않게 했습니다 — 사진마다 밝기가 달라 글자가 읽히다 안 읽히다 합니다.
- **설명과 자료 건수는 화면에서만 비켜 둡니다**(sr-only 방식). 문서에서 지우면
  화면낭독기 사용자가 도구가 무엇을 하는지 알 수 없습니다.
- 제목이 판 아래쪽에 앉으므로 사진마다 `object-position` 을 따로 잡아
  **주인공이 위쪽에** 오게 했습니다(지도는 사고지점 핀, 문자는 문안 윗줄,
  방제는 차체).
- 실제 휴대전화(390×750)에서 **세 칸이 온전히** 한 화면에 들어옵니다.

**눌렀다는 느낌은 `:active` 로 줍니다.** 손가락에는 호버가 없으므로 이것이
유일한 눌림 신호입니다 — 사진이 1.05배가 되고, 판이 짙어지고, 제목 줄이
오른쪽으로 밀리고, 둥근 화살표가 파랗게 찹니다.

⚠ iOS 사파리는 손가락으로 눌렀을 때 `:active` 를 잘 켜지 않습니다. `index.html`
맨 아래에 **아무 일도 하지 않는 `touchstart` 듣는 이**를 하나 달아 두었습니다
(널리 쓰는 방법). 그 한 줄을 지우면 iOS 에서 눌린 느낌이 사라집니다.
JS 가 꺼져 있어도 링크는 그대로 동작합니다.

### 움직이는 것 — 세 가지뿐

사용자가 "영상처럼 움직이는 것이 아니라, 사진 위에 문자들이 살아 움직이는
느낌"을 원했습니다. 그래서 딱 세 가지만 움직입니다.

| 무엇 | 어떻게 | 왜 |
|---|---|---|
| 머리띠 제목 (`heroIn`) | 열 때 한 번 올라옵니다 | 글자가 먼저 눈에 들어오도록 |
| 카드 세 장 (`pnIn`) | 열 때 한 번, 0.09초 간격으로 차례로 | 무엇이 몇 장 있는지 눈에 들어오게 |
| 머리띠 제목 낱말 | 열 때 0.1초 간격으로 하나씩 | 문구가 정적으로 보이지 않게 |
| 머리띠 사진 (`heroShot`) | 5초마다 다음 장으로, 그 사이 1.04배에서 제자리로 | 사용자 요청 · 첫 화면이 풍성해지도록 |
| 머리띠 문구 (`heroLead`) | 사진과 같은 때에 함께 바뀝니다 | 사진마다 그 자리에 맞는 말을 |
| 머리띠 점 (`heroDot`) | 지금 몇 번째인지 파랗게 | 몇 장이 더 있는지 보이게 |
| 사진 위 딱지 (`pnLb`) | 9초 주기로 하나씩 나타났다 사라집니다 | 사진 위의 글자가 살아 있게 |
| 카드 사진 | 마우스를 올리면 1.04배 | 누를 수 있는 것임을 알림 |

되풀이되는 것 가운데 **저절로 5초를 넘겨 움직이는 것(머리띠 넘김)에는 멈춤
단추**를 붙였습니다. 딱지는 사진 위 장식이라 멈춤 대상이 아닙니다.

지켜야 할 두 가지

1. **멈춘 상태가 곧 다 보이는 상태** 여야 합니다. 애니메이션을 모르는 낡은
   브라우저에서도 그대로 보이게 기본값을 '다 보이는 쪽'으로 두었습니다.
2. 모션을 줄이는 설정에서는 `animation:none` 으로 **끕니다.** 길이만 0 으로
   줄이면 무한 반복이 순식간에 되풀이돼 오히려 깜빡입니다.

**딱지에 수치를 적지 않습니다.** 거리·시간을 적으면 자료처럼 읽혀 잘못된 값을
주게 됩니다. 사진에 실제로 찍혀 있는 것의 이름(대피소·사고지점·방제장비 …)만
씁니다 — `tests/t9` 가 딱지에 숫자가 없는지 검사합니다.

### 도구 링크 바꾸기

각 카드의 `<a href="...">` 한 줄만 고치면 됩니다(`.tools > li > a`).
도구 순서는 **바꾸지 마세요** — `01 지도 → 02 문자 → 03 방제자원` 은 상사
피드백으로 정한 실제 업무 순서입니다.

### 이미지 자르기·투명화 (참고용 스니펫)

나중에 로고나 사진에서 필요한 부분만 잘라 배경을 투명하게 만들어야 할 때
Pillow(`pip install pillow`)로 간단히 처리할 수 있습니다. (지금 쓰는 로고·
패널 사진은 이 처리를 하지 않고 원본을 그대로/압축만 해서 씁니다 — 아래는
나중에 비슷한 작업이 필요할 때 참고용입니다.)

```python
from PIL import Image
im = Image.open("원본.png").convert("RGBA")
crop = im.crop((x0, y0, x1, y1))          # 필요한 영역만 좌표로 자르기
px = crop.load()
w, h = crop.size
for y in range(h):
    for x in range(w):
        r, g, b, a = px[x, y]
        if r > 244 and g > 244 and b > 244:   # 거의 흰색이면
            px[x, y] = (r, g, b, 0)           # 투명하게
crop.save("결과.png")
```

좌표를 모를 땐 흰색이 아닌 픽셀의 최소·최대 좌표를 스캔해 자동으로 경계를
찾을 수 있습니다(비어있지 않은 영역의 bounding box).

## ① 주민대피 문자생성기

대피·주민안내 **발송 지시를 받은 뒤** 사용하는 문안 작성 도구입니다.
대피 여부·대상지역·발송단계의 판단은 도구가 하지 않습니다.

### 화면

**한 화면에 한 가지만 묻습니다**(KRDS 단계형). 예전에는 왼쪽에 입력칸 여덟 개,
오른쪽에 문안 네 건이 동시에 떠 있었는데, 급할 때 어디를 먼저 봐야 하는지가
분명하지 않았습니다.

```
┌─ 발송 구분 3개 (가로) ────────────────────────────┐
│  실내대피 알림  │ 도로 우회 알림 │ 주민소산(대피명령) │
└───────────────────────────────────────────────────┘
┌─ 진행 표시 (누르면 그 걸음으로) ──────────────────┐
│ ✓사고유형 ✓발송정보 ③사고 발생 위치 ④문자 받을 지역│
│ ⑤사고물질 ⑥대피장소 ⑦문안 확인                    │
└───────────────────────────────────────────────────┘
┌─ 지금 걸음만 (가운데 한 줄) ──────────────────────┐
│ 사고 발생 위치   사고가 일어난 곳                  │
│ [사고 시·군·구] [사고 읍·면·동] [사업장·장소명]    │
└───────────────────────────────────────────────────┘
        [이전 — 발송 정보]        [다음 — 문자 받을 지역]
```

마지막 걸음(문안 확인)에서는 입력칸이 사라지고 문안만 보입니다.

- **걸음 수는 발송 구분에 따라 6~7개**입니다 — 대피장소를 쓰지 않는 구분에서는
  그 걸음이 아예 없습니다. 진행 표시를 눌러 아무 걸음으로나 건너뛸 수 있습니다.
  급할 때 아는 값부터 채우는 사람도 있고, ② 지도에서 값을 들고 오면 이미 채워진
  걸음도 있기 때문입니다. 다 채운 걸음에는 체크가 붙습니다.
- **필수 칸이 비어 있으면 문안을 만들지 않습니다.** 마지막 걸음에 "아직 채우지
  않은 칸이 N개 있습니다" 와 그 걸음으로 가는 단추가 대신 나옵니다. 예전에는
  `{시각}` 같은 표시가 그대로 남은 반쪽 문안이 보였는데, 급한 상황에서 그것을
  그대로 복사해 발송할 위험이 있었습니다.
- **집결지는 비워도 됩니다.** 집결지를 따로 두지 않는 지자체가 있어 필수에서
  뺐습니다. 비면 7번 문안이 `대피소[○○]으로 대피요망` 으로 나가고, 넣으면
  `대피소[○○]나 집결지[△△]으로 대피요망` 으로 나갑니다.
  **두 문장을 템플릿에 그대로 적어 두고 값이 있는 쪽을 씁니다** — 기계가 문장을
  잘라 붙이는 것이 아닙니다. 문안은 승인받은 표준(안)이라 조립해 만들면 안 됩니다
  (`data/templates.js` 의 `[[집결지:…]]` · `[[!집결지:…]]`).
- **문자 받을 지역**은 배경색을 넣어 눈에 띄게 했습니다. 사고가 난 위치와
  문자를 받을 지역을 혼동해 다른 지역에 잘못 보내는 사고를 막기 위한 것입니다.
- 발송 구분은 **제목만** 보여줍니다. 자세한 설명은 상단 안내 띠에 한 줄로 나옵니다.
  안내 띠는 **구분을 고른 뒤에만** 뜹니다 — 고르기 전에 "위에서 고르세요" 같은
  문구를 띄우면 바로 아래 큰 단추 3개가 이미 그 말을 하고 있어 같은 말을 두 번
  하는 셈이고, 첫 화면이 문구 한 줄만큼 밀려납니다.
- 종료·복귀 문안을 별도 구분으로 두지 않고 **각 구분 안에서 함께 생성**합니다.
  상황이 종료됐을 때 사고정보를 다시 입력할 필요가 없습니다.
- 지금 보낼 문안이 먼저 보이도록 **나중에 쓸 문안 그룹은 접어 둡니다.**
  제목을 누르면 펼쳐지고, 입력하는 동안 다시 닫히지 않습니다.
  접힌 그룹에 검사 오류가 있으면 제목 옆에 표시되므로 모르고 지나치지 않습니다.
- 필수 칸을 다 채운 뒤에도 **문안마다 따로 검사**합니다. 어떤 문안에만 쓰이는
  항목(7-1번 추가 안내의 집결 시각 등)이 비면 그 문안 카드 안에만 빨간 글씨로
  표시하고 그 문안만 복사를 막습니다 — 전체를 막는 배너로 두지 않습니다.
  판단이 필요한 사항(지역 불일치 등)만 위쪽에 주의 문구로 남습니다.
- 화면 위쪽은 **제목만** 둡니다. "다른 지자체 실제 발송 사례"는 본문에 펼쳐 두지
  않고 **버튼을 눌렀을 때만 창으로** 봅니다 — 사례가 계속 늘어나도(현재 42건,
  추후 100건 이상 추가 예정) 본문을 밀어내지 않도록 한 것입니다.
- **긴급재난문자와 자체 문자발송시스템은 색·테두리를 다르게** 표시합니다
  (긴급재난문자 = 남색 진한 머리표 + 굵은 좌측선, 자체 = 회색 옅은 머리표).
  발송 경로를 혼동해 잘못 복사하는 것을 막기 위한 것입니다. 인쇄물에서도 구분됩니다.
- 기본은 **밝은 화면**이고, 시스템 다크모드를 저절로 따라가지 않습니다. 대신
  오른쪽 위 **‘어두운 화면으로’** 단추로 KRDS 고대비 화면을 켭니다 — 사고는
  밤에도 나므로 야간 근무자·저시력 담당자가 직접 고를 수 있어야 합니다.
  한 번 고르면 세 도구 모두 그 상태로 열립니다(`assets/theme.js`).
- 물질정보는 요약 한 줄만 보이고, 필요할 때만 펼칩니다.
- 대피장소는 "지도에서 찾기" 또는 "목록에서 찾기" 를 눌렀을 때만 열립니다.
- 좁은 화면(720px 미만)에서는 진행 표시가 **지금 걸음의 이름만** 두고 나머지는
  번호만 보여줍니다 — 일곱 개 이름이 가로로 늘어서면 옆으로 밀려 지금이 어디인지
  안 보입니다. 모바일에서도 가로 스크롤이 없습니다.

### 발송 구분과 문안 대응

| 발송 구분 | 그룹 | 문안 |
|---|---|---|
| ① 실내대피 알림 | 발송 문안 | 2번(긴급) · 1번(자체) |
| | 상황종료 시 문안 | 6번(긴급) · 5번(자체) |
| ② 도로 우회 알림 · 실내대피 중일 때 | 발송 문안 | 4번(긴급) · 3번(자체) |
| | 상황종료 시 문안 | 6번(긴급) · 5번(자체) |
| ② 도로 우회 알림 · 대피명령 발령 중일 때 | 발송 문안 | 10번(긴급) · 9번(자체) |
| | 상황종료 시 문안 | 12번(긴급) · 11번(자체) |
| ③ 주민소산(대피명령) 알림 | 발송 문안 | 8번(긴급) · 7번 · 7-1번(자체) |
| | 상황종료 시 문안 | 12번(긴급) · 11번(자체) |

② 도로 우회 알림은 사고발생 **외** 지역용이므로 대피장소 입력칸이 없고,
사고 지점이 도로일 수 있어 `사업장·장소명` 칸을 **`도로명·장소명`** 으로 부릅니다.

### 발송 구분 안의 하위 분류 (도로 우회 알림)

도로 우회는 표준(안)이 문안을 두 벌로 줍니다 — 사고지역이 **실내대피 중**일 때
(4·3번)와 **대피명령 발령 중**일 때(10·9번). 그래서 생성 문안 칸 맨 위, 첫
문안 묶음 바로 위에 상황을 고르는 작은 칩 두 개를 두고 **고른 쪽 문안만**
보여 줍니다. 네 개를 한꺼번에 늘어놓으면 지금 상황과 맞지 않는 문안까지
훑어야 하고, 급할 때 그 자리에서 잘못 고를 여지가 생깁니다.

- 칩 앞에 `사고지역 상황` 같은 이름표는 두지 않습니다 — 칩 글씨가 이미 그
  말을 하고 있고, 결론은 아래 문안이지 이 줄이 아니므로 문안 묶음 머리표보다
  눈에 덜 띄어야 합니다. 화면낭독기용 이름은 `aria-label` 로 남깁니다.
- 손가락으로 누르는 화면에서는 글씨는 그대로 두고 높이만 40px 로 키웁니다.
- 고르기 전에는 문안을 아예 만들지 않고, 무엇을 고르라고 이름까지 적습니다.

**상황종료 문안**은 표준(안)에 도로 우회 전용이 따로 없습니다. 대신 종료 문안
네 개(6·5·12·11번)의 대상이 이미 "사고발생 지역 및 그 외 지역"이라 우회 안내를
받은 사람도 수신 대상입니다. 그래서 새로 짓지 않고, **각 상황과 짝이 맞는 것을
그 아래 접어 둡니다** — 실내대피 중이었으면 실내대피 해제 문안(6·5번),
대피명령 중이었으면 주민복귀 문안(12·11번).

자료 구조로는 발송 구분에 `분류` 를 두면 그 아래 `그룹` 이 들어갑니다
(`data/templates.js`). 고른 값은 `state.cat[구분id]` 에 남아, 다른 구분에 갔다
돌아와도 그대로입니다. 분류가 없는 구분은 지금까지처럼 `그룹` 을 바로 씁니다.

### 기능

- 「화학사고 재난문자 표준(안)」 12개 문안 자동 조합
- **사고유형 4종**(누출·화재·폭발·기타)에 따라 사고 표현이 자동으로 바뀜.
  화재·폭발은 "{물질} 관련 화재사고"처럼 **"관련"을 붙여** 표현합니다 —
  "{물질} 화재사고"라고만 쓰면 그 물질 자체가 타거나 터졌다는 뜻이 되어,
  그 물질을 취급하는 곳에서 났지만 물질과 무관한 화재(전기 화재 등)에는
  맞지 않는 문구가 나가기 때문입니다
- **사고물질 선택 목록** — 460종 전체를 스크롤로 훑어보거나 검색해서 고름.
  각 줄에 물질명·영문명·CAS·사고 발생건수 표시. 사고 많은 물질이 위로.
  물질명·영문명·CAS·유사명 어느 것으로도 검색됨 (`염산`·`불산`·`7664-41-7` 모두 가능).
  키보드 ↑↓ Enter Esc 지원. 목록에 없는 물질은 그대로 입력 가능
- **물질정보 460종 참고 패널** — 고른 물질의 성상·냄새, 증기밀도,
  화재·폭발 가능성, 사고유형별 참고 거리, 증상, 응급조치를 표시
- 사고 1건 = 한 세션. 발송 구분만 바꾸면 사고정보가 승계됨 (`sessionStorage`, 브라우저 닫으면 소멸)
- 한 구분에서 **긴급재난문자용·자체 시스템용**과 **알림·종료 문안**을 함께 생성
- 긴급재난문자 90자 초과 시 우선순위 축약 + **무엇을 뺐는지 표시**
- 전국 화학사고 대피장소 1,849곳 시·군·구별 선택 (오타·미등록 장소 방지)
  - **지도에서 찾기** — 아래 「지도에서 찾기」 참조
  - 목록에서 찾기 — 기존 드롭다운 방식도 그대로 남아 있음
- 한글 조사 자동 처리 (`황산이` / `염소가스가`, `경로당으로` / `학교로`)
- 사고 시·군이 발송기관과 같으면 자동 생략해 글자수 절약
- 필수 미입력, 예시값 잔존, 실내대피↔외부대피 혼재, 지역 불일치 검사
  (알림 문안과 종료 문안이 한 화면에 나오므로 **문안 하나하나의 단계로** 검사)
- 오류가 나오면 그 **문안 카드 안에 빨간 글씨로 표시**하고 그 문안만 복사를 막습니다.
  전체를 막는 배너는 없습니다 — 필수 미입력이든 90자 초과든, **그 항목·문안에만
  영향**을 줍니다. 예를 들어 대상지역을 안 쓰는 종료 문안은 대상지역이 비어 있어도
  그대로 복사할 수 있습니다
- 생성 기록 TXT 저장 (서버 로그가 없으므로 사후 확인용)
- 실제 발송 사례 42건 — "실제 발송 사례" 버튼을 눌렀을 때만 창으로 봄
  (비승인 자료로 명시, 물질별 필터, 추후 100건 이상 추가 예정)
- 입력칸에 예시값을 두지 않음 — 예시를 실제 값으로 착각해 발송하는 사고 방지
- 추가문의 전화번호는 문구에 넣지 않음 — 사고 시 문의 폭주로 대응이 어려워지는 것 방지

### 여는 방법

**홈페이지 게시** — 저장소 전체를 웹 경로에 올리고 `index.html` 로 연결

**단일 파일 배포** — `dist/` 안의 파일을 **하나씩** 옮겨 브라우저로 열면 됩니다.

## ② 주민 대피장소 찾기

전국 등록 화학사고 대피장소 1,849곳을 **배경지도(도로·건물·지명) 위에서** 확인하고,
사고지점 기준 거리·방위를 계산합니다.

① 도구 안의 "지도에서 찾기" 창과 **같은 엔진**(`assets/mapcore.js`)을 씁니다.
투영·거리 계산·배경지도가 같으므로 두 화면에서 같은 사고지점을 찍으면 같은 거리가
나옵니다. 이 화면은 창이 아니라 화면 전체를 쓰므로 아래 것들을 더 합니다.

### 고르기 창보다 더 하는 것

- **거리 눈금** — 사고지점 둘레에 500m·1km 처럼 떨어지는 거리로 고리를 그립니다.
  축척 막대만 있으면 특정 대피장소가 얼마나 떨어졌는지 눈으로 재야 하지만,
  고리가 있으면 몇 번째 고리 안팎인지로 바로 읽힙니다. 확대 정도에 따라 간격이
  자동으로 바뀌어 항상 2~3개가 보입니다.
- **행정구역을 넘어 찾기** — 사고지점을 찍은 뒤 `찾는 범위`를 반경(2·5·10·20km)으로
  바꾸면 시·군·구를 보지 않고 전국에서 찾습니다. 사고가 경계 가까이에서 나면 옆
  시·군 대피장소가 관내보다 가깝기 때문입니다.
  관내만 보고 있어도 **반경 5km 안에 다른 시·군·구 대피장소가 있으면 알려 줍니다**.
  (예: 광주 남구 경계 지점 — 관내 최근접 190m 옆에 서구 대피장소가 191m 에 있음)
- **시·군·구를 안 골랐으면 반경 5km 로 자동 전환** — 시·도/시·군·구를 고르지 않은
  상태에서 사고지점을 정하면 찾는 범위를 5km 로 잡습니다. 네 가지 방법(지도 클릭 ·
  주소·장소 검색 · 위경도 입력 · 내 위치) **모두** `setAcc()` 한 곳을 지나므로
  똑같이 동작합니다. 예전에는 이 처리가 검색·내 위치 쪽에만 있어서 **지도를 눌러
  찍으면 주변 대피장소가 하나도 안 나오는** 문제가 있었습니다.
  시·도나 시·군·구를 이미 골라 두었으면 그 선택을 존중해 바꾸지 않습니다.
- **없으면 한 칸씩 넓히는 단추** — 지금 범위 안에 대피장소가 없으면 요약 줄에
  `반경 10km 안에서 찾기` 처럼 **한 칸 넓은 범위를 권하는 단추**가 뜹니다(5 → 10 →
  20km). 좁은 화면에서는 `찾는 범위` 고르는 칸이 지도 한참 아래에 있어, 안내만
  하고 끝내면 정작 넓힐 방법이 화면에 없기 때문입니다. 20km 에도 없으면 단추 대신
  **더 넓힐 곳이 없다고 적습니다** — 누를 수 없는 단추를 남기지 않습니다.
- **요약 줄** — 가장 가까운 곳, 1·2·5km 안 개수, 영향 참고 반경 안 개수, 풍하방향
  개수를 한 줄로 보여줍니다. 목록을 훑지 않아도 "이 근방에 뭐가 있나"가 답이 됩니다.
- **연결선** — 고르거나 가리킨 곳까지 선을 긋고 거리·방위를 적습니다.
- **풍하방향 부채꼴** — 바람이 향하는 쪽 ±60° 를 칠합니다.
- **거리 막대** — 목록 각 줄에 거리를 막대로 그려 줄끼리 견주어 볼 수 있게 합니다.

### 기능

화면 위쪽 조건 줄에는 **주소·장소 검색 · 사고지점(찍기·내 위치·위도·경도) ·
영향반경 참고 물질 · 풍향 · 배경지도**를 두고, 시·도/시·군·구/찾는 범위처럼
"대피장소를 찾는" 기능은 오른쪽 목록 패널 위쪽으로 모았습니다(같은 흐름 —
어디서 찾을지 고르면 바로 아래에 결과가 나옴).

**사고지점 정하기는 조건 줄에 있습니다.** 예전에는 지도 아래쪽 반투명 띠에
있었는데, 이 도구에서 가장 먼저 하는 일인데도 지도에 가려 못 찾는 일이 있었습니다
(사용자 요청으로 옮김). 지도에 남은 것은 **도보 경로 · 거리 눈금** 두 개뿐입니다 —
그건 "지금 보고 있는 그림"을 켜고 끄는 것이라 지도 옆이 맞습니다.
③ 방제 물품·장비 찾기도 같은 자리입니다. 두 지도가 달라 보이면 안 되기 때문입니다.

- 시·도 / 시·군·구 선택(오른쪽 패널) → 관내 대피장소 표시
- **주소·장소 검색** — 두 가지를 함께 찾습니다.
  **도구 안 자료**(등록된 대피장소·시·군·구·읍면동)는 인터넷 없이 즉시 나오고,
  **사업장·건물 이름과 도로명 주소**는 브이월드 검색으로 찾아 뒤에 덧붙습니다
  (아래 "인터넷이 있을 때 더 되는 것" 참고).
  인터넷 결과는 좌표가 정확하므로 고르면 바로 사고지점이 되고, 도구 안 결과는
  근사 좌표(읍면동 평균 등)라 그 언저리로 이동만 하고 정확한 자리는 지도를 눌러
  찍게 합니다. 위도·경도 직접 입력도 그대로 있습니다
- **배경지도 3종** — 브이월드 일반지도 / 위성+도로명 / OpenStreetMap.
  안 되면 자동으로 다음 것으로 넘어가고 이유를 화면에 적습니다
- **지도 클릭 또는 위경도 입력**으로 사고지점 지정.
  찍으면 그 언저리로 자동으로 당겨, 거리 눈금이 쓸모 있는 크기로 잡힙니다
- 사고지점 기준 **직선거리·8방위** 자동 계산, 가까운 순 정렬
- **영향 참고 반경** — 물질 460종에서 검색하면 물질정보의 거리 값을 버튼으로 제시
  - 누출: 초기이격거리(전 방향) · 방호활동거리(풍하방향, 낮/밤)
  - 화재·폭발: 화재 동반 시 대피거리
  - 직접 입력도 가능. 반경 안에 든 대피장소는 빨간색 + 경고
- **풍향 선택(나침반)** → "풍향(불어오는 쪽)"이라는 말 자체가 헷갈리기 쉬워, 방위
  목록 대신 나침반에서 불어오는 쪽을 찍으면 그 반대쪽(풍하방향)으로 화살표와
  "OO쪽으로 퍼집니다" 문구가 함께 나타나도록 바꿨습니다. 지도 위 풍하방향(±60°)
  부채꼴 표시는 그대로입니다
- 이름·주소 **검색**, 이름순 / 가까운 순 / 수용인원순 **정렬**
- 드래그 이동 · 휠 확대축소 · 전체 보기 · 축척 막대 — 확대·축소 단추와 전체
  보기, 조건이 바뀌어 시야가 새로 잡힐 때는 순간이동 대신 **부드럽게 움직여**
  어디로 얼마나 옮겨 가는지 눈으로 좇을 수 있습니다(드래그·휠은 연속 동작이라
  지금처럼 그 자리서 바로 반응합니다)
- 대피장소 선택 시 주소·수용인원·관할부서 대표번호 표시, 이름/주소 복사,
  **카카오맵·로드뷰·네이버지도 열기** 링크
- 인쇄 지원 (조작 UI 는 빠지고 지도 + 목록 전체가 나옵니다)

### 내 위치 · 이동시간 · 가까운 3곳

현장에 나가 휴대전화로 열었을 때를 위한 것들입니다.

| 기능 | 설명 |
|---|---|
| **내 위치** | 브라우저에 들어 있는 위치 기능을 씁니다 — **인터넷이 끊긴 곳에서도 됩니다**(단말이 위성·기지국·와이파이로 직접 계산). 사고지점이 아직 없으면 내 위치를 사고지점으로 찍고 반경 5km 로 잡아, 단추 한 번에 주변 대피장소가 채워집니다. 이미 사고지점이 찍혀 있으면 **건드리지 않고** 파란 점만 더합니다 |
| 오차 범위 | 단말이 알려 준 오차를 옅은 원으로 함께 그립니다. 실내에서는 이 원이 수백 미터로 커지는데, 그게 보여야 좌표를 곧이곧대로 믿지 않습니다. 오차가 클 때는 알림에도 "지도를 눌러 정확한 자리로 고치라"고 적습니다 |
| **도보·차량 예상 시간** | "1.2km" 만으로는 대피 안내를 쓸 수 없습니다. 주민에게 실제로 필요한 값은 "몇 분"입니다. **400m 를 넘으면 도보와 차량을 나란히** 적습니다(`도보 12분 · 차로 3분`) — 대피 상황에서도 차로 움직이는 사람이 많고, 차량 시간이 함께 보여야 어느 쪽으로 안내할지 판단이 섭니다. 400m 이하는 차를 타는 것이 더 느려 도보만, 3km 를 넘으면 걸어서 대피시킬 거리가 아니므로 차량만 적습니다 |
| **가까운 3곳** | 지도 위에 세 줄을 겹쳐 띄웁니다. 급할 때 필요한 것은 훑어볼 목록이 아니라 "그래서 어디로 보내면 되는가"이기 때문입니다. 눌러서 바로 경로선까지 봅니다. 검색어로 목록을 걸러 놓아도 이 세 줄은 **항상 실제 최근접 3곳**입니다. 머리표를 눌러 접고 펼 수 있으며, **좁은 화면에서는 접힌 채로** 시작합니다 — 휴대전화에서 이 카드가 지도의 4분의 1 ~ 5분의 2 를 덮어 그 자리를 손가락으로 만질 수 없었기 때문입니다(가장 가까운 한 곳은 지도 위 요약 띠에 늘 적혀 있습니다) |
| 경로선 | 사고지점에서 고른 곳까지 굵게 긋고 거리·방위·소요시간을 적습니다. 배경지도 도로 위에서 묻히지 않게 흰 테두리를 깔았습니다 |

**이동시간은 어림값입니다.** 실제 길은 직선보다 돌아가므로, 직선거리에 우회계수
1.3(도시 도로망에서 실제 도로거리 ÷ 직선거리의 통상값)을 곱한 뒤 도보 4km/h 로
나눕니다. 차량은 거리에 따라 속도를 달리 잡습니다(가까울수록 신호·주정차로 느립니다).
화면에도 어림값임을 적어 확정된 소요시간으로 오해하지 않게 합니다.
도보 경로를 실제로 받아 왔을 때는 그 값이 이미 도로거리이므로 **우회계수를 다시
곱하지 않습니다**(`MC.trip(m, mode, roadKnown)` 의 세 번째 인자).

### 대피장소를 정했으면 그대로 문자로 (지도 → 문자 도구)

사고지점을 찍으면 오른쪽 목록 위에 **`이 내용으로 문자 만들기`** 단추가 생깁니다.
누르면 문자 작성 도구로 넘어가면서 지금까지 정한 것이 입력칸에 들어가 있습니다.

| 넘기는 것 | 어디서 |
|---|---|
| 사고 시·군·구 | 사고지점 주소 → 없으면 행정경계 판정 → 없으면 가까운 대피장소의 시·군·구 |
| 사고 읍·면·동 | 사고지점 주소(브이월드) → 없으면 2km 안 대피장소 주소에서 뽑음 |
| 사업장·장소명 | 장소 검색으로 찍었으면 **그 장소 이름**, 지도를 눌러 찍었으면 **사고지점의 도로명 주소**(예: `시청1길 1`) — 이름을 모를 때 그 자리를 가리키는 가장 정확한 말이기 때문입니다. 둘 다 없으면 비워 둡니다 |
| 대피소 | 고른 대피장소(없으면 가장 가까운 곳) |

### 사고지점 주소 알아내기

주민대피 문안은 `{시군} {읍면동} {사업장}에서 발생한` 처럼 읽습니다. 좌표만으로는
그 칸을 채울 수 없어 담당자가 지도를 보면서 따로 찾아 넣어야 했습니다 — 지도가
이미 아는 것을 다시 찾게 하는 셈이었습니다. 두 단계로 채웁니다.

| | 시·군·구 | 읍·면·동 | 도로명 |
|---|---|---|---|
| **인터넷 없이** | 화면에 그리는 그 행정경계로 판정(`MC.sggAt`) | 2km 안에 대피장소가 있으면 그 주소에서 | — |
| **인터넷이 되면** | 브이월드 주소로 덮어씀 (`ONLINE.revgeo`) | 〃 | 〃 |

- 어림값일 때는 요약 줄에 **`대략`** 을 붙이고, 문자 도구의 알림 띠에도
  "보내기 전에 확인하세요"라고 적습니다. 어림값을 확정값으로 오해하면
  엉뚱한 지역에 문자가 나갑니다.
- 알아내지 못한 칸은 **넘기지 않습니다.** 지어낸 값보다 빈 칸이 낫습니다.
- 경계선 자료는 약 244m 로 단순화된 것이라 시·군 경계 바로 옆에서는 틀릴 수
  있습니다. 그래서 인터넷이 되면 브이월드 쪽을 먼저 씁니다.

- 단추에 **무엇이 넘어가는지 미리 적습니다**(`이 내용으로 문자 만들기 (시군·대피소)`).
  눌러 보고 나서야 알게 하지 않기 위한 것입니다.
- 문자 도구에 도착하면 초록 띠로 **어느 칸에 무엇이 채워졌는지 그대로 보여 줍니다.**
  내가 넣지 않은 값이 칸에 들어가 있는 상태이므로, 모르는 채 발송되는 것이 가장
  위험합니다. ✕ 로 띠만 닫을 수 있고 값은 남습니다.
- **대상지역(문자 받을 지역)은 넘기지 않습니다** — 사고가 난 곳이 아니라 "어디까지
  보낼 것인가"라는 판단이고, 그 판단은 도구가 하지 않습니다. **발송 구분도 고르지
  않습니다** — 어느 문안을 보낼지는 지시받아 정하는 것입니다.
- 전달은 `sessionStorage`(`nics.sms.seed.v1`) 한 칸이며 **한 번 읽고 지웁니다.**
  새로고침해도 사용자가 고친 값을 다시 덮지 않습니다. 브라우저 밖으로 나가는 것은
  없고, 창을 닫으면 사라집니다.
- 단일 파일판(`dist/`)에는 옆에 문자 도구가 없으므로 이 단추를 **빼고 만듭니다**
  (`build/build_single.py`). 인터넷 기능(`assets/online.js`)과 `도보 경로` 켜기도
  같은 이유로 뺍니다 — 망분리 PC 에서 눌러도 할 일이 없는 것을 남기지 않습니다.

### 인터넷이 있을 때 더 되는 것 (② 대피장소만)

`assets/online.js` — **② 주민 대피장소 찾기만** 이 파일을 부릅니다.

| 기능 | 어디에 무엇을 보내나 | 안 될 때 |
|---|---|---|
| **사업장·건물 이름으로 찾기** | 브이월드(`api.vworld.kr`)에 검색어 | 도구 안 자료(대피장소 이름·시군구·읍면동)로만 찾음 |
| **사고지점 주소** | 브이월드(`api.vworld.kr`)에 사고지점 좌표 | 행정경계와 2km 안 대피장소 주소로 어림잡음 (`대략` 표시) |
| **도보 경로** | OSRM(`router.project-osrm.org`)에 두 지점 좌표 | 지금까지처럼 직선을 그림 |

**사업장명 검색** — "여수시청", "○○화학 여수공장"처럼 이름만 알아도 찾힙니다.
사고는 등록된 대피장소가 아니라 그런 곳에서 납니다. 도구 안 결과를 먼저 즉시
보여 주고 인터넷 결과는 도착하는 대로 아래에 덧붙이므로, 기다리느라 아무것도
안 보이는 시간이 없습니다. 인터넷 결과는 좌표가 그 건물의 것이라 정확하므로
**고르면 바로 사고지점으로 찍고 반경 5km 도 함께 잡습니다**(도구 안에서 찾은
시군구·읍면동은 평균 좌표라 지금처럼 지도를 한 번 더 눌러 찍게 합니다).

**도보 경로** — 직선은 "어느 쪽으로 얼마나"는 알려 주지만 걸어서 갈 수 있는
길인지는 알려 주지 못합니다. 강·철길·고속도로가 사이에 있으면 직선으로는 가까워도
한참 돌아가야 합니다. 고른 곳 **하나**에 대해서만 실제 경로를 받아옵니다.
목록과 '가까운 3곳'은 직선 어림값 그대로 둡니다 — 고를 때마다 세 건씩 더 부르면
느려지고, 급할 때 필요한 것은 목록의 정밀도가 아니라 지금 고른 한 곳의 실제 길입니다.

화면에서 둘을 구분할 수 있게 했습니다. 실제 경로는 **실선**에 "실제 도로" 표시가
붙고, 직선 어림값은 **긴 점선**에 "직선거리로 어림한 값"이라고 적힙니다.
받아 온 도로거리에는 우회계수를 다시 곱하지 않습니다(두 번 세면 안 됩니다).

`도보 경로` 스위치를 끄면 좌표를 내보내지 않고 직선만 씁니다. 대외 발표 전
위치를 밖에 내보내면 안 되는 상황에서 쓰라고 둔 것입니다.

> **③ 방제자원은 이 파일을 부르지 않습니다.** 업체 담당자 개인정보 취급 방침이
> 아직 정해지지 않아, 사고지점·업체 좌표를 바깥으로 내보내는 기능을 붙이지
> 않았습니다. 공용 엔진(`mapcore.js`)이 아니라 별도 파일로 둔 이유가 이것입니다 —
> 파일이 분리돼 있으면 "어느 화면이 무엇을 바깥으로 보내는가"가 각 페이지의
> `<script>` 목록만 봐도 드러납니다. ① 문자 작성 도구도 부르지 않습니다.

### 두 가지 대피처 — 화학사고 대피장소 · 이재민 임시주거시설

지도에 올릴 수 있는 대피처가 두 가지입니다. **지정한 목적도, 관리하는 곳도, 목록도
서로 다릅니다.** 어느 한쪽만 보면 근처에 있는 다른 쪽을 놓치므로 함께 켜 두고
색으로 구분합니다(초록 ● 화학사고 대피장소 · 보라 ● 이재민 임시주거시설).

| | 화학사고 대피장소 | 이재민 임시주거시설 |
|---|---|---|
| 출처 | 화학물질안전원 | 행정안전부 (공공데이터포털 오픈API) |
| 지정 목적 | 화학사고 시 주민 대피 | 재난 이재민 수용 |
| 자료 파일 | `data/shelters.js` | `data/tempshelters.js` |

목록 패널의 딱지 두 개로 켜고 끕니다. 딱지가 곧 범례이자 개수 표시입니다.
**둘 다 끄지는 못합니다** — 급할 때 잘못 눌러 빈 지도가 되는 일을 막습니다.
두 자료가 섞여 있을 때만 목록 각 줄에 어느 쪽인지 딱지가 붙습니다(한 종류만
보고 있으면 위 딱지에 이미 적혀 있어 붙이지 않습니다).

`data/tempshelters.js` 가 없으면 이 줄은 **아예 나오지 않고** 화면은 예전 그대로
화학사고 대피장소만 보여 줍니다. 자료를 받는 방법은 아래를 보세요.

#### 이재민 임시주거시설 자료 받기 (`build/fetch_tempshelter.html`)

원자료는 공공데이터포털 **행정안전부_이재민임시주거시설정보** 오픈API 입니다.
개발 환경에서는 그 서버에 닿지 않으므로, **인터넷이 되는 PC에서 한 번 받아**
만들어진 파일만 저장소에 넣는 방식으로 합니다(방제자원 좌표를 만드는
`build/geocode.html` 과 같은 방식).

1. `build/fetch_tempshelter.html` 을 저장소 폴더 그대로 둔 채 인터넷이 되는 PC에서 엽니다
   (옆에 `../data/shelters.js` 가 있어야 지역 이름을 맞출 수 있습니다)
2. **열면 저절로 받아옵니다.** 자료 주소와 인증키가 파일에 적혀 있어 입력할 것이 없습니다
3. **칸 짝짓기 표**로 원자료의 어느 칸을 무엇으로 읽었는지 확인합니다.
   원자료의 칸 이름은 해마다 조금씩 달라지므로 규칙(정규식)으로 찾고,
   무엇을 무엇으로 읽었는지 화면에 그대로 보여 줍니다
4. `tempshelters.js` 를 내려받아 `data/` 에 넣고
   `python3 build/build_single.py` 로 단일 파일판을 다시 만듭니다

브라우저 보안(CORS)으로 막히면, 주소창에서 JSON 을 직접 열어 저장한 뒤
`내려받아 둔 JSON 파일로 하기` 로 그 파일을 고르면 결과가 같습니다.

**자료를 파일로 내려받았다면** 오픈API 대신 이쪽이 더 간단합니다.

```bash
python3 build/make_tempshelters.py 내려받은파일.csv     # xlsx 도 됩니다
```

같은 규칙으로 같은 `data/tempshelters.js` 를 만듭니다.

> **집계표로는 지도를 만들 수 없습니다.** 같은 이름의 자료라도 시·도별
> 개소·수용능력만 있는 통계표가 있고, 시설 하나하나의 이름·주소·좌표가 있는
> 목록이 따로 있습니다. 필요한 것은 뒤엣것입니다. 집계표를 넣으면 페이지와
> 스크립트가 **파일을 만들지 않고 왜 안 되는지 알려 줍니다**
> (2026-08-13 에 오픈API `uddi:78c724b6-…` 가 집계표여서 실제로 걸렸습니다 —
> 51줄·개소와 수용능력만 있음).

> **인증키가 이 파일에 적혀 있습니다.** 열자마자 돌아가게 하려고 넣은 것입니다.
> 저장소를 공개로 두면 키도 함께 공개되며, 그 키로 할 수 있는 일은 공개된 자료를
> 내려받는 것뿐이지만 **하루 호출 한도는 소진될 수 있습니다.** 키가 샜다고 판단되면
> 공공데이터포털 마이페이지에서 다시 발급받아 `인증키·자료 주소 바꾸기` 칸을
> 고치면 됩니다(고친 값은 그 브라우저에 기억되어 다음부터 그 값으로 시작합니다).
> 자료 주소(uddi)도 갱신 때 바뀌므로 같은 자리에서 바꿉니다.

만들어지는 자료는 화학사고 대피장소와 **같은 줄 구조**라 같은 엔진이 그대로 씁니다.

```js
TEMPSHELTERS[시도][시군구] =
  [[시설명, 면적, 주소, 최대수용인원, 시설구분, 위도, 경도, 관리기관, 전화], ...]
```

- **좌표가 없는 줄은 넣지 않습니다** — 지도에 찍을 수 없고, 없는 좌표를 지어내면
  담당자가 그 자리로 사람을 보내게 됩니다
- 시·도/시·군·구 이름은 `data/shelters.js` 의 것에 맞춥니다(`경기` → `경기도`,
  `성남시 분당구` → `성남시`). 같은 시·군·구로 묶여야 함께 검색되기 때문입니다
- 대피장소가 한 곳도 없는 시·군·구도 버리지 않습니다 — 시·군·구 고르는 칸은
  두 자료의 지역 이름을 합쳐 만듭니다

### 하지 않는 것

- 어느 대피장소가 적절한지 **판단하지 않습니다**
- **이재민 임시주거시설이 화학사고에 적합한지 따지지 않습니다.** 재난 이재민
  수용을 목적으로 지정된 곳이며, 화학물질 방호 성능을 보고 고른 곳이 아닙니다
- 반경 원은 물질정보에 기재된 참고 거리이며 **확산 모델링 결과가 아닙니다**
- 목록·요약·'가까운 3곳'의 거리는 지형·도로를 고려하지 않은 **직선거리**입니다.
  **도보 시간도 그 직선거리를 통상 우회 비율만큼 늘려 잡은 어림값**이며,
  통제·정체·지형은 반영하지 않습니다. 화면에 "직선거리로 어림한 값"이라고 적힙니다
- 실제 도로 경로는 **지금 고른 한 곳**에만 붙습니다(인터넷 필요). 그 줄에는
  "실제 도로" 표시가 붙어 어림값과 구분됩니다. 길찾기 서버가 응답하지 않으면
  직선으로 되돌아가며, 화면이 멈추거나 비지 않습니다
- 풍하방향 부채꼴은 입력한 풍향의 반대쪽 ±60° 를 칠한 것으로,
  지형·풍속·물질 밀도를 반영하지 않습니다
- 배경지도는 **인터넷이 되는 환경에서만** 표시됩니다.
  망분리 환경에서는 행정경계선만 그리며, 거리·방위 계산은 그대로 동작합니다

## ③ 방제 물품·장비 찾기

흩어져 있는 방제자원 네 가지를 한 화면에 모아, 사고지점에서 가까운 순으로 찾아
바로 연락할 수 있게 합니다.

| 자원 | 언제 부르나 | 표시하는 것 |
|---|---|---|
| 폐기물 처리업체 | 회수한 오염물·폐기물 처리 | 허가 폐기물 종류·처리방식·일 처리량 |
| 방제장비 판매업체 | 흡착재·중화제·보호구 조달 | 취급 품목 |
| 중장비 업체 | 용기 이송·견인·굴착 | 장비 종류·대수 |
| 비상캡슐 보유기관 | 누출 봄베 밀봉·회수 | 캡슐 규격·수량 |

조작 방법은 ②와 같습니다 — 사고지점 찍기 → 거리순 목록 → 누르면 지도 가운데.
새로 배울 것이 없도록 일부러 같게 두었습니다.

### ②와 다른 것

- **필요한 자원으로 먼저 좁히기** — 사고 상황에서는 "폐기물 처리업체를 찾자"가
  아니라 "이걸 처리해야 한다"로 생각하게 됩니다. 그래서 종류 칩을 목록 맨 위에
  두고, 지도 마커도 종류마다 **모양을 다르게** 그립니다(● 폐기물 ■ 장비 ▲ 중장비
  ◆ 비상캡슐). 색만으로 나누면 배경지도 위에서 묻히고 색각 이상이 있으면
  구분되지 않습니다.
- **요약 줄이 종류별 최근접** — ②는 "가장 가까운 대피장소 하나"가 답이지만,
  방제자원은 종류마다 하나씩 필요합니다. 네 종류의 최근접 거리를 한 줄로 보여주고
  누르면 그 자원이 바로 선택됩니다(관내에 없으면 반경을 자동으로 넓힙니다).
- **바로 전화** — 번호가 `tel:` 링크라 휴대전화에서 누르면 걸립니다.
- **동원 목록** — 여러 곳을 담아 업체명·연락처·거리·보유장비를 한 번에 복사합니다.
  상황실 보고나 무전으로 부를 때 하나씩 옮겨 적는 수고를 덜기 위한 것입니다.
- **찾는 범위가 더 넓음** — 반경 10·20·50·100km. 방제자원은 관내에 아예 없을 수
  있어(비상캡슐은 시·군에 한 곳도 없는 경우가 흔합니다) 옆 시·도에서 불러야 하는
  상황이 실제로 생깁니다.
- **시작 화면에서 몇 글자만 쳐도 후보가 그 칸 아래에 뜹니다.** 눌러 고르면 그
  자리가 사고지점이 됩니다. 사업장 이름·주소·시·군·구·읍·면·동은 물론
  **보유 장비 이름과 운영기관**으로도 찾습니다(흡착포·굴착기·해경 등) —
  원자료의 "보유·처리 내용" 칸을 함께 견줍니다.

  > **고쳐 둔 것** — 이 검색은 ② 주민 대피장소 찾기에서 코드를 옮겨 온 것인데,
  > ②는 대피장소 **줄 배열**을 훑는 반면 ③의 `resTree()` 는 "어느 시·도에 어느
  > 시·군·구가 있는가"만 담은 표(값이 `1`)입니다. 그래서 글자를 칠 때마다
  > `rows.forEach is not a function` 이 나 **도구 안 검색이 통째로 죽어
  > 있었습니다** — 인터넷이 될 때만 결과가 나왔습니다. 지금은 `allRes()` 를
  > 훑습니다. 화면끼리 코드를 옮길 때는 자료 구조가 같은지 먼저 확인해야 합니다.

### 개인정보 — 공개판·내부판 두 벌

방제자원은 대부분 민간업체라 **대표번호는 야간·휴일에 연결되지 않습니다.**
실제로 쓰이는 것은 담당자 직통인데 그건 개인정보라 공개 배포에 넣을 수 없습니다.
②(대피장소)처럼 그냥 빼 버리면 법적으로는 안전하지만 정작 필요할 때 쓸모없는
도구가 됩니다 — ②는 상대가 지자체 부서라 당직실이 24시간 받지만 ③은 다릅니다.

그래서 "넣느냐 빼느냐"가 아니라 **"누구에게 주느냐"**로 나눴습니다.

| | 데이터 | 결과 파일 | 담기는 것 |
|---|---|---|---|
| 공개판 | `data/resources.js` | `화학사고_방제물품장비_찾기.html` | 업체명·주소·좌표·보유자원·**대표번호** |
| 내부판 | `data/resources.internal.js` | `..._내부용.html` | + **담당자 이름·직통번호** |

```bash
python3 build/make_resources.py       # 두 데이터 파일 생성
python3 build/build_single.py            # 공개판만
python3 build/build_single.py --internal # 내부판도 함께
```

화면·기능은 완전히 같고 데이터 파일만 다릅니다. 안전장치:

- 내부판 데이터와 결과 파일은 **`.gitignore` 로 저장소에서 제외**됩니다
- 내부판으로 빌드하면 화면 위에 **빨간 "내부용 · 외부 공유 금지" 띠**가 자동으로 뜹니다
- 파일명에도 `_내부용` 이 붙습니다

내부판은 메일로 돌리지 말고 내부망 공유폴더·업무포털로만 전달하세요. 정적 HTML에
비밀번호를 거는 것은 의미가 없습니다 — 소스 보기로 데이터가 그대로 보여서 보호가
아니라 착각만 줍니다. 보호는 파일이 아니라 **배포 경로**에 겁니다.

> **한 가지 주의** — 방제·중장비 업체는 소규모가 많아 **대표번호가 곧 대표자 개인
> 휴대폰인 경우가 흔합니다.** 그래서 "대표번호는 무조건 안전"이 아닙니다. 실제
> 기준은 *허가대장·사업자등록처럼 공개된 행정자료에 실린 사업장 연락처인가* 입니다.
> 공개 배포 전 **원내 개인정보 보호 담당 부서 확인이 필요합니다.**

### 지금은 예시 자료입니다

실제 자료를 넣기 전이라 화면 확인용 가짜 자료(105건)가 들어 있습니다. 실제 업체가
아니며 전화번호도 실제 번호가 아닙니다. 화면 위에 **"예시 자료"** 띠가 뜹니다.

실제 자료로 바꾸려면 `build/make_resources.py` 의 `make_sample()` 자리에 원본 엑셀
읽기 코드를 넣으면 됩니다. 출력 형식(`RESOURCES` 구조)은 그대로 두세요 — 화면
코드가 그 형식을 씁니다.

**좌표 변환이 필요합니다.** 원자료에 위경도가 없고 주소만 있는데, 망분리 환경에서는
실시간 변환을 쓸 수 없습니다. 인터넷이 되는 PC에서 **한 번만** 주소→좌표 변환
(도로명주소 API·브이월드 지오코더 등)을 돌려 결과를 데이터에 박아 넣으세요.
변환에 실패한 건은 시·군·구 중심 좌표로 대체하고 `ap:false` 로 두면 화면과 목록에
**"대략 위치"** 로 정직하게 표시됩니다.

### 하지 않는 것

- 어느 자원을 동원할지, 처리 방법이 적절한지 **판단하지 않습니다**
- 거리는 **직선거리**라 실제 도착 시간과 다릅니다
- **차량 도착시간은 어림값입니다.** ②와 같은 방식(직선거리 × 우회계수 1.3)이되
  거리대별 평균속도(시가지 25 / 중거리 40 / 장거리 55km/h)로 나눕니다.
  방제자원은 장비를 싣고 오므로 도보가 아니라 차량 기준으로 적으며,
  **장비 상·하차 시간은 빠져 있습니다** — 실제 도착은 이보다 더 걸립니다.
  내 위치로 사고지점을 찍을 때 반경을 20km 로 잡는 것도 같은 이유입니다
  (②는 5km). 방제자원은 관내에 아예 없는 경우가 흔합니다
- **업체는 폐업하고 담당자는 바뀝니다.** 보유 장비도 다른 현장에 나가 있을 수
  있습니다. 값은 기준일 시점의 것이므로 **동원 전 전화로 가동 여부·보유 상태를
  확인해야 합니다.** 급할 때 죽은 번호는 없는 것보다 나쁩니다

## 지도에서 찾기

도로·건물·지명이 보이는 배경지도 위에 관내 대피장소를 찍어 보여주고, 지도의 점이나
오른쪽 목록을 눌러 고릅니다. 여러 곳 동시 선택되며, 고른 곳을 대피소·집결지 등
원하는 칸에 넣습니다.

**앞 걸음에 적은 사고 위치 자리에서 열립니다.** 시·군·구를 다시 고르고 지도를
끌어 찾아갈 일이 없습니다. 여는 순간 사고지점이 찍혀 있고 목록도 가까운 순입니다.

- ② 주민 대피장소 찾기에서 넘어왔으면 그때 찍은 **좌표 그대로** 씁니다.
- 손으로 적은 시·군·구·읍·면·동만 있으면 그 이름으로 **어림잡습니다** —
  읍·면·동 경계 자료가 없어, 그 안에 있는 대피장소들의 좌표 평균을 씁니다
  (`MAPCORE.placeAt`). 몇백 미터 틀릴 수 있습니다.
- 어림잡은 값일 때는 창 위에 붉은 줄로 **무엇으로 어림잡았는지**와 "자리가
  다르면 다시 찍으라"는 안내가 뜹니다. 어림값을 실제로 잰 값과 눈으로 구분하지
  못하면 안 되기 때문입니다.

| 기능 | 설명 |
|---|---|
| 고르면 그 자리로 이동 | 고른 대피장소를 화면 중앙으로 부드럽게 옮기고, 멀리 보고 있었으면 가로 약 1.4km 로 당깁니다. **이미 가까이 보고 있으면 확대를 바꾸지 않습니다** — 주변을 비교하며 고르는 흐름을 끊지 않기 위한 것입니다. 해제할 때는 움직이지 않습니다 |
| 검색 | 이름·상세시설명·주소·시설구분으로 걸러냅니다. 지도 마커도 함께 걸러집니다 |
| 정렬 | 이름순 / 사고지점 가까운 순 / 수용인원 많은 순 |
| 사고지점 찍기 | 지도를 눌러 사고지점을 지정하면 대피장소마다 **직선거리·8방위**가 나오고, 가까운 순으로 자동 정렬됩니다. 어림잡아 열린 자리를 고칠 때도 이것을 씁니다 |
| 전체 보기 (⤢) | 관내 대피장소를 **전부** 담도록 시야를 넓힙니다. 열었을 때의 '주변만' 시야와 구분됩니다 |
| 영향 참고 반경 | 입력한 사고물질의 물질정보에서 거리 값을 뽑아 버튼으로 제시합니다(직접 입력도 가능). 반경 안에 든 대피장소는 붉게 표시하고 "확산방향을 확인하세요" 경고를 붙입니다 |
| 수용인원 합계 | 고른 곳들의 수용인원을 더해 보여줍니다 — 대피 인원과 견주어 볼 수 있게 |
| 이미 넣은 곳 이어받기 | 다시 열면 그 칸에 들어 있는 곳이 체크된 상태로 시작합니다. 한 곳만 보태고 싶을 때 처음부터 다시 고르지 않아도 됩니다 |
| 주소 표시 | 고른(가리킨) 곳의 도로명주소·수용인원·사고지점까지의 거리를 지도 아래에 적습니다 |
| 외부 지도로 확인 | 목록 각 항목에서 **카카오맵 · 로드뷰 · 네이버지도**를 새 창으로 엽니다(인증키 불필요) |

거리·방위·반경은 **참고 표시**입니다. 어느 대피장소가 적절한지, 대피 범위를 어디까지
잡을지는 도구가 판단하지 않습니다. 반경은 물질정보에 적힌 거리이며 확산 모델링이 아닙니다.

### 좌표 처리

지도는 **화면 픽셀 좌표계**로 그립니다. SVG 렌더링은 내부적으로 float32(유효자리 7자리)를
쓰기 때문에, 세계좌표(0~1)를 viewBox 에 그대로 넣으면 확대할수록 필요한 분해능이
1e-12 수준까지 내려가 도형이 사라집니다(실제로 확대하면 마커와 이름표가 없어졌습니다).
투영은 배정도인 자바스크립트에서 하고 SVG 에는 픽셀 값만 넘깁니다. 덤으로 선 굵기·
글자 크기·마커 크기가 확대와 무관하게 일정해집니다.

## 배경지도

**"지도에서 찾기" 창은 도로·건물·지명이 보이는 배경지도 위에 대피장소를 찍어 줍니다.**
기본으로 켜져 있습니다. 인터넷이 되는 환경을 전제로 합니다.

화면 위쪽에서 배경을 골라 쓸 수 있습니다.

| 배경 | 출처 | 인증키 | 쓰임 |
|---|---|---|---|
| 일반지도 | 브이월드 (국토교통부) | 필요 | 기본. 도로·건물·지명 |
| 위성+도로명 | 브이월드 | 필요 | 위성영상 + 도로명 겹쳐보기 |
| OpenStreetMap | OSM 기여자 | 불필요 | 브이월드가 안 될 때 자동 대체 |

### 배경이 안 뜨는 일이 없도록

`data/basemap.js` 의 `대체순서` 에 적힌 순서대로 시도하고, **앞의 것이 안 되면
자동으로 다음 것으로 넘어갑니다.** 브이월드 인증키가 잘못되었거나 활용 도메인이
등록되지 않았거나 서버 장애여도, 인증키가 필요 없는 OpenStreetMap 으로 바뀌므로
배경 없는 지도가 화면에 남지 않습니다.

전환이 일어나면 **왜 안 됐는지 화면에 띠로 표시**하고, 타일 주소를 새 창으로
열어보는 링크를 함께 줍니다. 그 창에 뜨는 메시지가 실제 원인입니다
(인증키 오류인지, 도메인 미등록인지 등). 조용히 넘어가지 않습니다.

### 브이월드 인증키

```
① https://www.vworld.kr → 오픈API → 인증키 발급 (2D 배경지도 / WMTS)
   · 활용 도메인에 이 도구를 올릴 주소를 반드시 등록
② data/basemap.js 의  인증키: "발급받은 키"
③ python3 build/build_single.py    ← dist/ 단일 파일도 쓸 때만
```

③ 은 `dist/` 단일 파일을 다시 만드는 단계입니다. **홈페이지 게시만 한다면 ② 까지로
끝입니다** — 저장소를 올리는 방식은 브라우저가 `data/basemap.js` 를 직접 읽습니다.

- 인증키는 브라우저에 노출됩니다(웹 지도 API 공통). 등록한 도메인에서만 동작합니다.
- **`file://` 로 직접 열면** 브이월드가 타일을 거부할 수 있습니다(Referer 없음).
  이때도 OpenStreetMap 으로 자동 전환되므로 지도는 보입니다.
- 인증키를 비워 두면 브이월드를 건너뛰고 바로 OpenStreetMap 을 씁니다.

### 좌표계

배경 타일·행정경계선·대피장소 마커를 모두 **웹 메르카토르(EPSG:3857)** 로 그리므로
서로 어긋나지 않습니다. 브이월드 WMTS 는 `z/y/x`(행→열), OSM 계열은 `z/x/y` 순서라
주소 틀에서 구분해 둡니다.

투영·거리 계산·타일 받기·행정경계선 그리기·**내 위치·이동시간 어림·경로선**은
**`assets/mapcore.js` 한 곳**에 모아 두었습니다. ① 의 고르기 창(`assets/shmap.js`),
② 주민 대피장소 찾기(`map/app.js`), ③ 방제자원(`res/app.js`)이 같은 코드를 쓰므로
세 지도가 어긋나지 않고, 타일 대체 규칙이나 도보 속도 같은 것을 고칠 때 한 번만
고치면 됩니다.

그리기는 **화면 픽셀 좌표**로 합니다. 세계좌표(0~1)를 viewBox 에 그대로 넣으면
SVG 내부 float32(유효자리 7자리) 때문에 확대할수록 도형이 떨리거나 사라집니다.

### 카카오·네이버 지도를 배경으로 쓰지 않은 이유

두 곳은 타일 주소를 직접 부르는 방식(WMTS/XYZ)을 공개하지 않고 전용 자바스크립트
SDK 를 불러오게 되어 있습니다. 대신 고른 대피장소를 **카카오맵·네이버지도에서
열어보는 링크**를 목록의 각 항목에 두었습니다(인증키 불필요, 새 창).

실제 Chromium 을 띄워 화면을 눌러 보고 확인합니다(문안 생성·지도·모바일·접근성·
단일 파일·자료 변환까지). 화면을 고쳤으면 관련 묶음을, 커밋 전에는 모두 돌립니다.
`playwright` 는 이미 깔린 것을 링크로 가져다 쓰므로 따로 설치할 것이 없습니다.
배경지도 타일을 못 받아 나는 `ERR_TUNNEL_CONNECTION_FAILED` 는 정상입니다.

데이터를 `.json` 이 아닌 `.js` 로 둔 이유: `file://` 로 열었을 때 `fetch()` 는 차단되지만
`<script src>` 는 동작하므로, 망분리 환경에서도 모듈 구조 그대로 쓸 수 있습니다.

### 무엇이 올라가고 무엇이 안 올라가는가

Pages 는 올린 것을 전부 공개하므로 화면이 실제로 부르는 것만 골라 올립니다.

| 올라감 | 안 올라감 | 이유 |
|---|---|---|
| `index.html` `assets/` `data/` `sms/` `map/` `res/` | | 화면에 필요 |
| `dist/` (공개판 3개) | | 망분리 PC로 옮길 사람이 여기서 내려받게 |
| | `source/` (원자료 26MB) | 대피장소 목록·실제발송사례 원본을 인터넷에 둘 이유가 없음 |
| | `build/` `docs/` | 화면과 무관 |
| | 내부판 자료 전부 | `.gitignore` 로 저장소에 없음 |

워크플로는 올리기 **전에** 내부판 데이터·담당자 항목·내부용 단일파일이 섞였는지
검사하고, 하나라도 걸리면 배포를 중단합니다. 올린 뒤 지우는 것보다 낫습니다.

### 배포 전에 알아 둘 것

- **저장소가 공개 상태입니다.** Pages 에 올리지 않은 `source/` 원자료도
  `github.com` 저장소 페이지에서는 이미 누구나 내려받을 수 있습니다.
  대외 공개가 곤란한 원자료가 있다면 저장소를 비공개로 바꾸거나 원자료를
  저장소에서 빼야 합니다(비공개 저장소의 Pages 는 유료 요금제가 필요합니다).
- **브이월드 인증키가 `data/basemap.js` 에 그대로 들어 있습니다.** 공개 저장소이므로
  이미 노출된 상태입니다. 정식 배포 전에 키를 다시 발급받고, 발급 시 **활용 도메인에
  `rlawogns221221221-create.github.io` 를 등록**해야 브이월드 배경지도가 뜹니다.
  등록 전에는 배경이 자동으로 OpenStreetMap 으로 넘어가므로 화면은 정상 동작합니다.
- **내 위치 찾기는 `https://` 에서만 됩니다.** Pages 는 https 라 그대로 되지만,
  사내 웹서버에 `http://` 로 올리면 브라우저가 위치 사용을 막습니다.

## 갱신 방법

**문안이 바뀌면** — `data/templates.js` 수정 → `data/version.js` 의 `문안근거`·`반영일` 갱신
→ `python3 build/build_single.py`

**데이터가 갱신되면** — `source/` 의 원본 파일 교체 → `build/make_data.py` 의 파일명·기준일 수정
→ `python3 build/make_data.py` → `python3 build/build_single.py`
→ `data/version.js` 의 출처·기준일 갱신

```bash
pip install openpyxl xlrd
python3 build/make_data.py      # shelters · materials · stats · cases 재생성
python3 build/make_boundary.py  # 행정경계 재생성 (경계 원자료를 바꿨을 때만)
python3 build/build_single.py   # dist/ 단일 파일 3개 빌드
```

**브라우저에서 한 번 받아 오는 자료** — 개발 환경에서 바깥 서버에 닿지 않아,
인터넷이 되는 PC에서 페이지를 열어 받고 결과 파일만 `data/` 에 넣습니다.
둘 다 없어도 화면은 그대로 돕니다(그 기능만 빠집니다).

| 페이지 | 만드는 파일 | 무엇 |
|---|---|---|
| `build/fetch_tempshelter.html` | `data/tempshelters.js` | 이재민 임시주거시설 (행안부 오픈API) |

## 초안 단계에서 확인이 필요한 사항

이 초안은 **업로드된 5개 원자료만으로** 만들었습니다. 다음은 아직 확정되지 않았습니다.

1. **글자수 산정 방식** — 실제 재난문자방송시스템과 대조 필요.
   기관명 자동 부기분이 90자에 포함되는지 등. 대조 후 `data/version.js` 의
   `글자수_검증여부` 를 `true` 로 변경하세요.
2. **망분리 여부** — 지자체가 어느 망에서 문안을 작성·송출하는지에 따라
   배포 형태(홈페이지 / 단일 파일)가 결정됩니다.
3. **표준(안) 원문 교정 5건** — `docs/표준안_대비_변경점.md` 참조. 원내 검토 필요.
4. **관리부서·연락처** — `data/version.js` 에 기재해야 합니다.
5. **기관명 위치** — 표준(안)은 문구 앞, 실제 사례는 문구 끝이 다수. 방침 결정 필요.
6. **사고유형별 문안 표현** — 화재·폭발·기타 문구는 표준(안)에 규정이 없어
   이 도구가 새로 만든 것입니다. 원내 검토 필요.
7. **배경 경계선 출처** — 통계청 센서스용 행정구역경계(2018) 기반이며 라이선스 명시가
   없는 2차 가공물입니다. 정식 배포 전 국가공간정보포털 등 정본 데이터로 교체를 권장합니다.
   `build/make_boundary.py` 의 입력 파일만 바꾸면 됩니다.
8. **물질별 행동요령** — 현재 도구는 물질에 따라 행동요령을 **바꾸지 않습니다**.
   표준(안) 행동요령을 그대로 쓰고, 물질정보는 참고 표시와 경고로만 제공합니다.
   물질별 행동요령을 문안에 넣을지는 별도 검토가 필요합니다(90자 제약과 충돌).
9. **브이월드 배경지도 실제 동작 확인** — 인증키는 발급 시 등록한 활용 도메인에서만
   동작합니다. 게시할 주소에서 일반지도·위성+도로명이 실제로 뜨는지 확인하세요.
   안 뜨면 화면에 이유가 표시되고 OpenStreetMap 으로 자동 전환됩니다.
10. **OpenStreetMap 사용 방침** — 브이월드가 안 될 때의 대체 배경으로 넣었습니다.
   공공기관 서비스의 상시 배경으로 쓸지는 원내 검토가 필요합니다
   (OSM 재단은 대량·상업적 타일 사용을 권장하지 않습니다). 빼려면
   `data/basemap.js` 의 `대체순서` 에서 `"osm"` 을 지우면 됩니다.
11. **외부 지도 확인 링크** — 카카오맵·네이버지도로 여는 링크를 대피장소마다 두었습니다.
   외부 사이트로 나가는 링크이므로, 홈페이지 게시 시 외부링크 표기 방침을 확인하세요.
   불필요하면 `assets/shmap.js` 의 `extLinks()` 를 빈 문자열로 바꾸면 사라집니다.
12. **자료 출처·기준 표시 제거** — 화면을 간소화하면서 "자료 출처·기준"(문안근거·
   대피장소·물질정보·사고통계 출처 및 글자수 상한 검증여부 등)을 화면에서 뺐습니다.
   데이터 자체는 `data/version.js` 에 그대로 있으니, 필요할 때 그 파일을 열어
   확인하거나 화면에 다시 노출할 위치를 정하면 됩니다.
